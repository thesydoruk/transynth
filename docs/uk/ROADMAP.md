# Дорожня карта

> **English version:** [../en/ROADMAP.md](../en/ROADMAP.md)
>
> Відкритий веб-інструмент для локалізації модів Fallout 4.
> Переклад на базі LLM (Ollama / OpenAI) + пам'ять перекладів + багатопрохідне вирівнювання.
> Натхненний [ESP-ESM Translator](https://www.nexusmods.com/skyrimspecialedition/mods/921) — але відкритий, веб-нативний та AI-орієнтований.

---

## Що вже реалізовано ✅

Фундамент і основні функції повністю працюють:

| Область | Що працює |
|---------|-----------|
| **Робота з плагінами** | Нативний парсер ESP/ESM/ESL + BA2 + STRINGS: витягування усіх перекладних рядків, застосування перекладу назад у плагін; працює на будь-якій ОС без зовнішніх залежностей |
| **LLM-переклад** | Провайдери Ollama (локально, безкоштовно) та OpenAI; маскування плейсхолдерів і глосарію; пакетна обробка; retry з експоненційним backoff; автоматичний fallback між провайдерами |
| **Пам'ять перекладів (TM)** | Навчання TM з пар модів (оригінал + переклад) або мультимовних модів (автодетект до 8 локалей, згортання клонів); 5-прохідне вирівнювання: hash → EDID → path → fuzzy → embeddings |
| **TM автозастосування** | Заповнення неперекладених рядків з TM за anchor (FormID+Path), EDID або нормалізованим текстом — з оцінкою впевненості |
| **Веб-інтерфейс** | React SPA + Fastify API: таблиця рядків з inline-редагуванням, кольорове кодування статусів, пакетний LLM-переклад (SSE-прогрес), пошук і фільтрація, схвалення/відхилення, дашборд прогресу |
| **Глосарій** | CRUD глосарійних термінів; автоматичне підставлення у LLM-промпт під час перекладу |
| **Поширення перекладу** | Зберігаєш переклад → автоматично заповнює всі ідентичні вихідні рядки по моду |
| **Пошук і заміна** | Regex/literal масова знайти-замінити з попереднім переглядом (dry-run) |
| **Diff модів** | Порівняння двох версій мода: додані / видалені / змінені рядки |
| **Інфраструктура** | Docker (multi-stage build, cli/dev/web сервіси), ESLint + Prettier, структуроване логування, TypeScript strict mode |

## Milestone 1 — Система зберігання і керування перекладами 🗄️ `v1.0`

> Повноцінна система для збереження, відстеження та управління перекладами: схема бази даних, стани, версіонування, API.

- [ ] **Схема бази даних** — design та міграції: таблиці для рядків перекладу, статусів, приміток; зовнішні ключі, індекси на `formId`, `edid`, `path`, `status`
- [ ] **Стани перекладу** — state machine: `untranslated → in_progress → translated → reviewed → rejected`; масова зміна статусів через Web UI та CLI
- [ ] **Версіонування перекладів** — зберігати кожну ревізію рядка (попередній текст, timestamp, опціонально автор); перегляд та відкат до попередньої версії
- [ ] **REST API для перекладів** — повний CRUD для рядків перекладу; batch update; фільтрація за `status`, `modId`, `signature`, `formId`, вільним текстом
- [ ] **Експорт / імпорт** — CLI `db:export` (вивантаження всіх перекладів у JSON / CSV); `db:import` для відновлення або злиття
- [ ] **Примітки перекладача** — поле note / comment для кожного рядка; відображення у Web UI

## Milestone 2 — Стабілізація 🛡️ `v1.1`

- [ ] **Юніт-тести** — vitest: `parseCsv`, `mask/unmask` round-trip, `alignPairs`, `normalizeForHash`, `ingestCsvRows`

- [ ] **E2E тест** — export → translate → apply round-trip на реальному невеликому моді
- [ ] **Крайні випадки** — порожні плагіни, моди без STRINGS, CSV лише із заголовками, Unicode edge cases (CJK, RTL)
- [ ] **Документація для користувача** — гайд з налаштування (Windows / Docker), покроковий туторіал "переклади свій перший мод"
- [ ] **UX помилок** — зрозумілі повідомлення у Web UI (LLM недоступний, помилка імпорту мода, непідтримуваний формат плагіна)

## Milestone 3 — Нативний парсер плагінів 🔧 `v1.2`

> Читання та запис ESP/ESM/BA2/STRINGS нативно. Повністю автономна робота на будь-якій ОС.

- [x] **STRINGS reader** — парсинг `.STRINGS` / `.DLSTRINGS` / `.ILSTRINGS` файлів (бінарний формат: `count(u32) + dataSize(u32) + entries[{id:u32, offset:u32}] + textBlob`)
- [x] **STRINGS writer** — генерація нових STRINGS файлів з перекладами
- [x] **BA2 reader** — розпакування Bethesda Archive 2 (GNRL тип), zlib-декомпресія окремих файлів; витягування STRINGS з BA2
- [x] **ESP/ESM reader** — парсинг бінарного формату: `TES4 → GRUP → Record → Subrecord`; витягування перекладних subrecords з контекстом (FormID, EDID, Signature, Path); обробка zlib-стиснених записів; localized vs embedded рядки
- [x] **ESP/ESM writer** — модифікація subrecords з перекладами, перерахунок розмірів записів, збереження стиснених записів
- [x] **CLI імпорт** — `src/cli/importMod.ts`: нативний імпорт мода
- [x] **Юніт-тести** — round-trip STRINGS read→write, BA2 extraction, ESP record parsing на тестовому моді

## Порівняння з ESP-ESM Translator

| Функція | ESP-ESM Translator | Цей проєкт |
|---|---|---|
| Платформа | Windows десктоп (Delphi) | Веб (будь-яка ОС, браузер) |
| Вихідний код | Закритий | Відкритий |
| Завантаження ESP/ESM/ESL | Нативний парсер | Нативний парсер (вбудований) |
| Двигун перекладу | Google Translate, DeepL, ChatGPT | Ollama (локально, безкоштовно), OpenAI (хмара); підключаються провайдери |
| Пам'ять перекладів | BDD файли, статичні бази по грі | SQLite TM, навчена з будь-яких пар модів, автовирівнювання |
| Алгоритм зіставлення | FormID, EDID, текстовий збіг | 5-прохідний: hash → EDID → path → fuzzy (fuzzball) → embeddings |
| TM автозастосування | Так (lookup у базі) | Так (anchor + EDID + text_norm, з оцінкою впевненості) |
| Глосарій | Так | Так (БД + Web UI CRUD + автопідставлення в LLM-промпт) |
| Масовий пошук-заміна | Так (матриця замін) | Так (regex/literal, dry-run, Web UI) |
| Diff версій мода | Ні | Так (додані/видалені/змінені рядки) |
| Переклад MCM/FOMOD | Так | Заплановано (Milestone 5) |
| Експорт TMX | Ні | Заплановано (Milestone 6) |
| Багатокористувацьке рев'ю | Ні | Заплановано (Milestone 8) |
| Поширення перекладу | Ні | Так (автозаповнення ідентичних рядків) |
| SSE живий прогрес | Ні | Так (Server-Sent Events) |
| Читання BSA/BA2 | Так | Так (нативний BA2 reader) |
| Декомпіляція скриптів | Так (частково) | Поза межами проєкту |
