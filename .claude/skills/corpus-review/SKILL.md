# Вичитка всього корпусу

Так зроблено вичитку Fallout 4 + DLC 2026-10-21: 166 279 рядків у 1 395 батчах, 38,9 %
рядків виправлено, і ~40 тис. рядків модів (42,7 % виправлено). Звіт і журнал рішень —
`doc/reviews/fo4-uk-2026-10-21/`. Стиль, рід, регістр, голоси й канон — скіл
`fo4-uk-translate`; цей скіл — лише конвеєр.

## 0. Узгодь з користувачем до старту

- **Обсяг**: які моди (ids — `CLAUDE.local.md`), скільки рядків, скільки батчів (≈ рядки / 110).
- **Моделі**: у вичитці Opus брав діалоги, квести й прозу; Sonnet — предмети, UI, обличчя і
  прозу, де робота зводиться до підстановки канону (UFO4P).
- **Як запускати агентів**: хвилями через Agent tool (до 10–12 паралельно, по два батчі на
  агента). Workflow — лише якщо користувач сам попросив оркестрацію.
- **Запис у базу** — тільки з явного дозволу; спитай перед першою хвилею запису.
- Робоча тека — поза репо (scratchpad або архів), бо там тисячі файлів.

## 1. Підготовка

- Канон актуальний: `src/games/creation-engine/data/names/fo4-uk.json`, глосарій у БД.
- Рядки, що дослівно збігаються з уже вичитаним текстом (той самий EN), заповни спершу з
  нього й познач окремою provenance (у вичитці модів — `tm_fo4_final_review`): агенти бачать їх
  як `context_only` і не переписують канон.

## 2. Батчі — `npm run review:batches`

```
npm run -s review:batches -- --mod <id> [--mod <id>…] --out <dir> [--context-provenance <p>]
```

Лише читає БД. На проді — у контейнері web (`CLAUDE.local.md`), потім скопіюй `<dir>` до себе.
Діалоги йдуть цілими розмовами (сцени квесту в порядку фаз, далі гілки й топіки) з мовцем,
адресатом і родом; решта — за сім'ями промптів гри; у кожному батчі `names` — канонічні назви,
які він згадує, і `qa_hints`. Формат — [batch-format.md](batch-format.md).

## 3. Агенти

Кожен агент отримує [agent-prompt.md](agent-prompt.md) з підставленими шляхами й своїми
`batch_id`. Він читає скіл `fo4-uk-translate` (SKILL.md і довідки), читає батч повністю,
пише `<dir>/fixes/<batch_id>.json` і сам проганяє валідатор, доки `rejected` не спорожніє або
не лишаться лише хибні відхилення (тоді пояснює їх у відповіді). Після кожної хвилі:

- збери з відповідей нові імена/назви (`en → uk`) і рішення, що виходять за межі батча, у
  `<dir>/DECISIONS.md`; канонічні — внеси в канон, щоб наступні батчі їх бачили (перебудуй
  ще не роздані батчі);
- конфлікти між агентами розв'язуй до запису, корпусним каноном, а не рішенням одного батча.

## 4. Перевірка й запис

```
npm run -s review:validate -- --dir <dir> --all
npm run -s translations:apply -- <dir>/fixes/<id>.checked.json --dry-run
npm run -s translations:apply -- <dir>/fixes/<id>.checked.json --provenance agent_final_review --model <id моделі>
```

`translations:apply` пише лише ті рядки, де в базі досі `old` (решта — `stale`: перечитай і
переглянь), фіксує ревізію з `batch_id` у примітці, оновлює QA і reference base. Деталі —
скіл `translation-apply`.

## 5. Уніфікація корпусу

Після всіх батчів — проходи по всьому корпусу:

1. Свіжий знімок вичитаного тексту (SELECT id, EN, переклад) у файл.
2. Для кожного варіанта назви/терміна — **спершу порахуй** у знімку, скільки разів який
   варіант стоїть; канон — те, що каже корпус і глосарій, а не одне рішення батча.
3. Правила-заміни з регексами; біля кирилиці — тільки lookarounds `(?<![Ѐ-ӿ])`, бо JS `\b` —
   лише ASCII (через це у вичитці мовчки не спрацювали 154 рядки).
4. Правки як `{id, old, new}`, де `old` — зі **свіжого** знімка; далі validate → apply.
5. Повторний прогін правил по новому знімку має давати 0 влучань.

## 6. Завершення

- Рядки, прочитані без змін, — статус `reviewed` (окремою командою, з дозволу).
- `npm run qa:refresh -- --target-lang uk`, `npm run rag:index-missing`. Голос нічого
  вручну не потребує: змінений озвучений рядок переозвучить наступний `missing`-job.
- Звіт у `doc/reviews/<гра>-<мова>-<дата>/`: обсяг, процес, статистика за сім'ями й модами,
  проходи уніфікації, відкриті питання користувачу, `DECISIONS.md`. Без хостів і шляхів.

## Уроки

- Оболонка псує бекслеші в heredoc і `node -e` — скрипти пиши інструментом Write і запускай файлом.
- Кожен агент кладе допоміжні скрипти у власну підтеку з унікальною назвою: паралельні агенти
  перезаписують однойменні файли.
- UFO4P-подібні патчі вирівнюються з ваніллю за FormID із зсувом — шукай двійника за EN.
- Частка правок 10–30 % — норма для машинного перекладу; 80 % означає переписування, 2 % —
  неуважне читання. Стеж за цим у звітах агентів.
