# Формат батча і правок

Батч — `<dir>/batches/<batch_id>.json` (будує `npm run review:batches`; типи —
`src/review/types.ts`).

```json
{
  "batch_id": "fallout4esm-dialog-001",
  "mod": "Fallout4.esm",
  "mod_id": 33,
  "game": "fo4",
  "family": "dialog",
  "names": { "Faneuil Hall": "Фейніл-Голл" },
  "units": [
    { "unit_id": "conversations:000229E1", "kind": "conversation", "label": "MQ102", "lines": [] }
  ]
}
```

- `family` — сім'я промпту гри: `dialog`, `prose` (термінали, книги, записки), `quest` (квести,
  повідомлення), `item`, `face`, `mcm`, `default`.
- `names` — канонічні назви (як у грі), які згадує батч. Вживай саме їх, відмінюючи. Назву, яку
  батч сам визначає (FULL запису NPC/локації), сюди не кладуть — вона на рев'ю.
- `units` — читати цілком: `conversation` (усі сцени квесту в порядку фаз), `branch`, `topic`
  (дерево топіка), `loose` (діалог без графа), `record` (один термінал/квест), `group` (серія
  предметів зі спільним EDID-стовбуром).

## Поля рядка

| Поле                            | Що означає                                                                                                           |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`                            | id англійського рядка; саме його повертай у правці                                                                   |
| `kind`                          | `response` (репліка вголос, NAM1), `prompt` (пункт колеса, RNAM — завжди гравець), або поле запису (`FULL`, `DESC`…) |
| `src` / `tr`                    | оригінал / поточний переклад, який редагуєш                                                                          |
| `speaker`, `speaker_gender`     | хто говорить: `male` / `female` / `any` (гравець без розгалуження статі) / `unknown`                                 |
| `addressee`, `addressee_gender` | до кого; `Player` + `any` — до гравця, стать невідома                                                                |
| `variant`                       | `"2/3"` — умовна альтернатива тієї самої фази, не наступна репліка                                                   |
| `branch_depth`                  | глибина гілки в дереві топіка                                                                                        |
| `ctx`                           | контекст з імпорту (часто ім'я мовця)                                                                                |
| `sig`, `field`, `edid`          | запис недіалогового рядка; EDID підказує, що це                                                                      |
| `narrator_gender`               | рід автора записки; `(inferred)` — виведено, не довіряй сліпо                                                        |
| `context_only`                  | лише для контексту (сусідній батч або вже канон) — **не правити**                                                    |
| `qa_hints`                      | підказки QA й попереднього аудиту — перевір, не вирок                                                                |
| `voice_variant`                 | номер озвученої відповіді, на переклад не впливає                                                                    |

## Правки — `<dir>/fixes/<batch_id>.json`

```json
{
  "batch_id": "fallout4esm-dialog-001",
  "reviewed": 134,
  "fixes": [
    {
      "id": 6525206,
      "old": "Та якого хріна ти знову до мене причепилася?",
      "new": "Якого хуя тобі знову треба?",
      "reason": "gender,voice",
      "note": "адресат — гравець (any): причепилася вгадує стать"
    }
  ],
  "notes": ["speaker metadata looks wrong for 6525300: Piper's line attributed to Nick"]
}
```

- `old` — **точна** копія `tr`; інакше правку відхилять.
- `new` — увесь новий текст рядка, не diff.
- `reason` — коди через кому: `meaning`, `gender`, `register`, `calque`, `voice`, `glossary`,
  `grammar`, `consistency`, `placeholder`.
- `note` — одне речення навіщо; можна пропустити для очевидного.
- `notes` — проблеми, які не виправити наявними даними (хибна атрибуція мовця, дивний оригінал).
- Без `context_only`-рядків і без правок, де `new` == `old`. Лише валідний JSON.

## Валідатор — `npm run review:validate`

Пише `<id>.checked.json` з `ok` і `rejected[{fix, why}]`. Відхиляє: невідомий id,
`context_only`, порожній `new`, `old` ≠ поточному перекладу, `new` == `old`, повторний id,
змінені теги/плейсхолдери, слеш-форми роду, жодної кирилиці, латинські слова, яких немає ні в
оригіналі, ні в поточному перекладі, різку зміну довжини, ремарку без дужок, загублений знак
питання. Хибне відхилення (бренд латиницею тощо) — лиши й поясни.
