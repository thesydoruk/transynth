## Формати експорту

Pipeline може створювати чотири типи вихідних артефактів:

| Формат          | Файл                                   | Призначення                                                    |
| --------------- | -------------------------------------- | -------------------------------------------------------------- |
| **STRINGS**     | `.strings`, `.dlstrings`, `.ilstrings` | Зовнішні таблиці рядків, які читає рушій гри                   |
| **Patched ESP** | `.esp` / `.esm`                        | Плагін мода з вшитими перекладами                              |
| **BA2 Archive** | `.ba2`                                 | Архів Fallout 4/76 із перекладеними STRINGS-файлами            |
| **BSA Archive** | `.bsa`                                 | Архів Skyrim SE/LE та FO3/FNV із перекладеними STRINGS-файлами |
| **Project ZIP** | `.zip`                                 | Упакований набір для розповсюдження                            |

## STRINGS-файли

Fallout 4 читає string data з бінарних таблиць, що лежать поруч із плагіном мода.
Типовий реліз локалізації містить:

```text
MyMod_en.STRINGS
MyMod_en.DLSTRINGS
MyMod_en.ILSTRINGS
```

Гра використовує три формати string tables:

| Розширення   | Формат                                    | Для чого використовується                       |
| ------------ | ----------------------------------------- | ----------------------------------------------- |
| `.STRINGS`   | null-terminated UTF-8 strings             | Загальний текст: назви, книги, описи            |
| `.DLSTRINGS` | `uint32 length + text + null terminator`  | Діалоги в меню розмов                           |
| `.ILSTRINGS` | Такий самий binary layout, як у DLSTRINGS | NPC topics, Pip-Boy notes, внутрішні інфо-рядки |

На стороні гравця перекладені `.STRINGS`, `.DLSTRINGS` і `.ILSTRINGS` файли кладуться в `Data\Strings\`.

Цей формат потрібен лише для **localized mods**, де текст винесений у зовнішні string tables. Для non-localized mods, де текст зберігається прямо в plugin binary, використовується [Patched ESP](#patched-esp).

## Patched ESP

Альтернатива STRINGS-файлам — записати переклади безпосередньо в копію ESP/ESM-плагіна.

Цей варіант використовується для **non-localized mods**, де текст зберігається у subrecord fields усередині plugin binary, наприклад `FULL` або `DESC`.

Під час експорту інструмент:

1. бере оригінальний ESP/ESM snapshot, збережений під час імпорту;
2. проходить усі записи, для яких є переклад у базі;
3. переписує відповідні subrecord fields перекладеним текстом;
4. віддає binary-compatible ESP, який гравець кладе у `Data\`.

Важливе попередження: patched ESP завжди базується на **тому оригінальному файлі мода, який був імпортований**. Якщо автор мода випустив оновлення, треба повторно імпортувати нову версію і заново робити експорт, інакше patched ESP буде зібраний поверх застарілого файлу.

## BA2-архів

Інструмент може упаковувати згенеровані STRINGS-файли у `.ba2`, тобто в стандартний архівний формат Fallout 4 для модових assets.

Ім’я створеного архіву відповідає канону Fallout 4:

```text
{PluginStem} - Main.ba2
```

Наприклад, для `MyMod.esp` архів матиме ім’я `MyMod - Main.ba2`.

Усередині архіву STRINGS-файли кладуться за шляхом:

```text
Strings\{filename}
```

Наприклад: `Strings\MyMod_uk.STRINGS`.

Гра автоматично підхоплює BA2-архіви, якщо вони названі за схемою `{PluginStem} - {Name}.ba2` і відповідний ESP активний у load order.

Поточний експортований BA2 — це **uncompressed GNRL archive (version 1)** для максимальної сумісності з різними версіями гри й mod managers.

Кнопки **Export BA2** і **Export ZIP** в toolbar редактора обидві генерують BA2; у варіанті ZIP цей BA2 додатково запаковується разом з patched ESP, якщо він застосовний.

## Project ZIP

Project ZIP може містити:

- patched ESP, якщо він потрібен;
- STRINGS-файли або BA2-архів із ними;
- готовий набір для розповсюдження.

Кнопка **Export ZIP** у Mod Editor запускає серверну генерацію ZIP, після чого браузер одразу завантажує файл.

Іменування ZIP:

```text
{PluginStem}_{targetLang}.zip
```

Наприклад: `MyMod_uk.zip`.

ZIP створюється у **store mode** без додаткового стискання, бо BA2 і ESP вже є бінарно упакованими файлами й майже не виграють від повторної компресії.

Важлива примітка: автоматичний `README.txt` у ZIP **не додається**. Якщо ви публікуєте переклад на Nexus Mods або деінде, інструкції зі встановлення треба додати самостійно.

## Запуск експорту

Усі export buttons розташовані у **toolbar редактора мода** у верхній частині сторінки.

1. Відкрийте мод у редакторі зі списку Mods.
2. Переконайтеся, що в toolbar вибрані правильні **Source language** і **Target language**.
3. Натисніть потрібну кнопку експорту.

| Кнопка             | Що завантажується                                                          |
| ------------------ | -------------------------------------------------------------------------- |
| **Export STRINGS** | Сирі `.STRINGS`, `.DLSTRINGS`, `.ILSTRINGS`                                |
| **Export ESP**     | Patched plugin з вбудованими перекладами                                   |
| **Export BA2**     | Один архів (`.ba2` для FO4/FO76 або `.bsa` для SSE/SLE/FO3/FNV) із STRINGS |
| **Export ZIP**     | `.zip`-пакет: архів + patched ESP, залежно від типу мода                   |

Поки сервер готує файл, кнопка показує стан `Exporting…`.

## Що включати в реліз перекладу

| Тип мода          | Мінімальний реліз     | Рекомендований реліз |
| ----------------- | --------------------- | -------------------- |
| Localized mod     | Loose STRINGS files   | BA2 archive          |
| Non-localized mod | Patched ESP           | Patched ESP          |
| Mixed             | STRINGS + Patched ESP | Project ZIP          |

Практичний checklist перед публікацією:

1. Перевірте переклад у реальній збірці Fallout 4 або Skyrim SE.
2. Додайте зрозумілі інструкції зі встановлення.
3. Вкажіть і кредитуйте автора оригінального мода.
4. Обов’язково зазначте, на якій версії базового мода побудовано переклад.
5. Позначте реліз тегами мови, щоб його було легше знайти.

## Часткові експорти і чернетки

Експорт можна робити на будь-якому етапі, навіть якщо переклад ще не завершено.
Неперекладені рядки у вихідних файлах автоматично підміняються оригінальним текстом.

Експорт використовує fallback `COALESCE(translation, source_text)`:

- якщо переклад є, записується він;
- якщо перекладу немає, записується вихідний source text;
- порожніх string slots у результаті не лишається.

Якщо для одного рядка є кілька перекладацьких спроб, вибирається найякісніший варіант за пріоритетом:

```text
reviewed > human > draft > tm > fuzzy > auto > rejected
```

Практично це означає, що чернетковий експорт корисно зробити рано, ще до повного завершення перекладу, щоб виявити layout issues, проблеми з placeholders та контекстом.

## Інваріанти експорту

Поточний export pipeline перевіряється regression-тестами на невеликому **golden corpus** із канонічних STRINGS, DLSTRINGS та ILSTRINGS-файлів.

Ці тести фіксують такі інваріанти:

1. **Зберігається інвентар файлів.** Якщо локалізований мод мав три string tables, експорт поверне ті самі три таблиці; змінюється лише locale suffix.
2. **Невідомі ID ігноруються.** Якщо в базі є translation row для ID, якого немає у вихідному файлі, він не потрапляє в результат.
3. **Відсутні переклади падають назад у source text.** Неперекладені slots не стають порожніми.
4. **UTF-8 коректно переживає round-trip.** Не-ASCII текст зберігається в `.strings`, `.dlstrings`, `.ilstrings` і BA2 output.
5. **BA2 output структурно передбачуваний.** Архів містить лише згенеровані string tables під `Strings\` і дотримується канонічного шаблону іменування Fallout 4.

Цей corpus навмисно синтетичний і компактний. Він є страховкою від регресій, але не замінює перевірку в реальній грі на справжніх модах.
