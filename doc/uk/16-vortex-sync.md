# 16 — Vortex: агент і ручний синк

> [!WARNING]
> **Експериментальна можливість.** Агент читає реальний стейдж Vortex і реальну
> інсталяцію гри і пише лише в теку завантажень Vortex. Почніть із `--dry-run`
> і перевіряйте результат, перш ніж на нього покладатися.

Стейдж Vortex (розпаковані папки після FOMOD) і офіційні файли гри потрапляють в
**окрему групу** на сервері. Група не перетирає моди, залиті через веб-UI або Nexus.
Дзеркалить її **резидентний агент** на машині з Vortex; переклад і озвучення
запускаються зі сторінки Vortex у веб-UI, коли їхні хости увімкнені.

---

## Агент

### Встановлення

На Windows, де видно стейдж і гру, у клоні репозиторію:

```text
npm run vortex:agent -- --init
```

пише `%APPDATA%\Transynth\vortex-agent.json`. Заповніть `gameDir` (тека гри), `api`
(адреса сервера) і `token` (`TRANSYNTH_CLI_TOKEN` сервера; змінна середовища з тим самим
ім'ям перекриває файл). `stagingPath` і `downloadsDir` за замовчуванням вказують туди, куди
Vortex ставить їх сам (`%APPDATA%\Vortex\<гра>\mods` і `%APPDATA%\Vortex\downloads\<гра>`);
якщо ви переносили їх у налаштуваннях Vortex, впишіть нові шляхи.

```text
npm run vortex:agent -- --dry-run     # інвентар і load order, жодного звернення до сервера
npm run vortex:agent -- --once        # один тік, синк за потреби, вихід
npm run vortex:agent                  # цикл до Ctrl+C
```

Щоб агент жив постійно, зареєструйте завдання планувальника, яке стартує при вході
(`schtasks /create /sc onlogon /tn TransynthVortexAgent /tr "cmd /c cd /d <клон> && npm run vortex:agent"`)
з перезапуском при збої, або викликайте `--once` раз на кілька хвилин.

### Що робить сам

Кожні `pollSec` (30 с) агент дивиться на список тек стейджа і на файли порядку
завантаження (`vortex.deployment.msgpack`, `plugins.txt`, `loadorder.txt`). Після зміни
чекає `settleSec` (90 с) тиші, бо Vortex ставить мод крок за кроком і тільки потім
деплоїть, а тоді:

1. хешує інвентар (плагіни, таблиці рядків, MCM, потрібні BA2, розпаковані кліпи) через
   кеш за розміром і mtime, тож багатогігабайтні архіви гри читаються один раз;
2. `plan` на сервері, `upload` лише нових чи змінених юнітів;
3. `import` → `carry` (перенесення перекладів і готових тактів з попередньої версії);
4. `tm` — ті самі tm-apply-джоби, що й кнопка TM у редакторі; читає еталонну базу, тож
   офіційні ESM, DLC і знайомі моди отримують вичитаний переклад одразу;
5. надсилає серверу поточний load order і переможців файлів. Якщо змінився лише порядок,
   відправляє тільки його, без заливки.

`autoStages` у конфігу — стеля: `import`, `carry` або `tm`. Вище агент не піде, і конфіг
з іншим значенням не завантажиться.

### Чого не робить ніколи

LLM-переклад, перевірка, skip-detect, gender-detect, озвучення, експорт. Хости LLM і TTS
не завжди увімкнені, тому ці етапи — кнопки на сторінці Vortex; кнопка вимкнена, поки
`/api/services` не бачить живого хоста потрібного типу.

### Ленгпак

Коли сервер має новий готовий ленгпак, агент скачує його у `downloadsDir` під ім'ям
`Transynth_<гра>_<мова>_langpack_r<N>.zip` (спершу `.part`, потім перейменовує), і Vortex
показує архів у вкладці Downloads та пропонує встановити. У стейдж агент нічого не пише і
в теці завантажень нічого не видаляє. Вимкнути: `"deliverLangpack": false`.

### Ролики

З `"videos": true` ролики входять у юніти як файли мода: `Data/Video` — до головного
майстра, `Video/` стейджу — до його мода; у zip замість ролика йде маніфест, а самі файли
агент досилає тим роликам, які сервер зареєстрував і попросив через heartbeat. Читає, дублює
й записує ролики сам сервер (ffmpeg в образах web і worker, BinkMix від RAD у
`bethesda-tools`), а продубльовані ролики йдуть у ленгпаку групи як `Video/<file>.bk2`;
більше на машині з Vortex нічого не ставиться. Ролик, який Vortex розгорнув із нашого ж
ленгпака, агент читає з `<файл>.vortex_backup` — оригіналу, який Vortex відкладає поруч.
Решта — у табі «Медіа» режиму
озвучки мода. Див. [Дубляж роликів](18-video-dubbing.md).

### Стан і журнал

`%LOCALAPPDATA%\Transynth\vortex-agent\`: `state.json` (сигнатури, останній прогін,
доставлений ленгпак), `hash-cache.json`, `journal.log` (JSON lines). Помилка синку
відкладає повтор на 1, 2, 4 … до 30 хвилин; нова зміна у стейджі скидає відлік. Heartbeat
іде щотіку: сторінка Vortex показує стан, останній синк, що очікується, останню помилку.

## Сторінка Vortex

Сторінка гри → посилання **Vortex** (`/games/<гра>/vortex`): панель агента, кнопки етапів
(Повторити TM, LLM-переклад, Перевірка, Skip-detect, Gender-detect, Озвучення, Експорт
ленгпаку), поточний прогін з прогресом по модах і кнопкою Стоп, історія прогонів, останній
ленгпак для скачування. Кожна кнопка створює окремий прогін; поки він триває, інші кнопки
вимкнені.

Етап `tm`, `llm`, `verify`, `skip`, `gender` чи `voice` запускає для кожного мода групи
той самий джоб, що й редактор, по одному моду за раз: LLM і TTS бачать по одному джобу,
бейджі в редакторі й кнопки зупинки працюють як завжди. `import`, `carry` і `export` ідуть
усередині одного джоба `vortex-sync`.

## Ручні запуски (CLI)

`npm run vortex:sync` лишається для разових операцій:

```text
npm run vortex:sync -- --staging "<стейдж>" --game-dir "<гра>" --api http://127.0.0.1:3200 --stage tm
npm run vortex:sync -- --staging "<стейдж>" --game-dir "<гра>" --channel game
```

Етапи: `plan` → `upload` → `import` → `carry` → `tm` → `llm` → `verify` → `skip` →
`gender` → `voice` → `export`; `--stage`, `--from`/`--to` ріжуть діапазон. `--channel game`
— лише офіційні masters (патч гри), `--channel mods` — лише стейдж. `--out` зберігає
ленгпак у вказаний файл. `--dry-run` друкує інвентар без API. Етапу `install` більше нема:
ленгпак доставляє агент через теку завантажень Vortex.

## Група на сервері

Ключ групи: гра + шлях стейджа. Повторний синк оновлює ту саму групу. Кожен мод і кожен
master гри — окремий рядок; нова версія (інший content hash) не затирає стару, у групи є
`is_current`. Carry-over і ленгпак лише всередині групи; TM читає всю базу й еталони, пише
тільки в групу. Сторінка Моди показує їх разом із модами, завантаженими вручну, з міткою **Vortex**; фільтр
**Джерело** (з’являється, коли є група) лишає лише **Локальні імпорти** або одну групу
`Vortex · …`. Редактор той самий.

Ленгпак збирається за load order і переможцями файлів з deployment-маніфесту: у нього
потрапляють офіційний канал гри і лише ті стейдж-моди, чия папка є в deployment (мод
увімкнений у Vortex). Якщо є синтез, додаються `UASoundPack.esp` і `UASoundPack - Main.ba2`.

## Версії гри

Офіційні ESM з `Game\Data`, яких немає в стейджі, збираються в `vortex_game_releases`.
Лейбл — ProductVersion з `Fallout4.exe`. Новий патч = новий реліз; попередній лишається.

## Токен

Якщо на сервері задано `TRANSYNTH_CLI_TOKEN`, агент і CLI мають передати його в записах:
plan, заливка юнітів, старт діапазону, heartbeat, load order. Кнопки сторінки Vortex і
всі читання відкриті, як решта застосунку.

Після зміни схеми: `npm run db:init`.
