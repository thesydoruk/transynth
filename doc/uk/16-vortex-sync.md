# 16 — Vortex sync

Імпорт розпакованого стейджа Vortex і офіційних файлів гри в **окрему групу** на сервері. Група не перетирає моди, залиті через веб-UI або Nexus.

---

## Команда

На Windows, де видно стейдж і гру:

```text
npm run vortex:sync -- ^
  --staging "D:\Vortex Mods\fallout4" ^
  --game-dir "D:\Games\Fallout4" ^
  --api http://127.0.0.1:3200 ^
  --game fo4 --tgt-lang uk
```

Джерело — **розпаковані папки** після FOMOD, не `.zip`/`.7z` у стейджі. Zip на дроті лише транспорт цього дерева.

Ігрові/модові BA2/BSA **не розбираємо локально** — потрібні архіви їдуть як є. Беремо лише те, що зараз імпортується або треба для синтезу:

- плагіни (`.esp` / `.esm` / `.esl`)
- таблиці рядків, `.pex`, MCM / `Translate_*.txt`
- GNRL `* - Main.ba2`, `* - Interface.ba2`, `* - Voices*.ba2` (і такі ж BSA)
- розпаковані кліпи `Sound/Voice/**/*.fuz|xwm|wav`

Meshes / Sounds / Textures / Animations і інший асетний дамп не заливаємо. Папки без плагіна й без MCM/Interface txt (наприклад сам F4SE) пропускаємо — імпортер їх не реєструє.

`--dry-run` друкує інвентар без API.

## Етапи

`plan` → `upload` → `import` → `carry` → `tm` → `llm` → `export` → `install`

`--stage tm` не хешує стейдж і не крутить `vortex-sync`. CLI стартує ті самі `tm-apply` джоби, що кнопка TM у редакторі, і чекає кожен мод групи.

- `--stage tm` — один етап
- `--from import --to tm` — діапазон
- `--channel game` — лише офіційні masters (патч гри)
- `--channel mods` — лише стейдж
- `--install-staging` — розпакувати ленгпак як `Transynth UK Langpack` у стейдж
- `--apply-order` (типово увімкнено) — злити ленгпак за Vortex load order і переможцями файлів
- `--no-apply-order` — старий абетковий merge
- `--plugins-txt` / `--vortex-profile` — явний `plugins.txt`, `loadorder.txt` або профіль

Експорт читає `%LOCALAPPDATA%\Fallout4\loadorder.txt` та `vortex.deployment.msgpack` у стейджі. У ленгпак потрапляють офіційний канал гри і лише ті стейдж-моди, чия папка є в deployment (мод увімкнений у Vortex). Прапорець ESP у `plugins.txt` не рахується. Плагіни в ZIP ідуть у порядку load order; колізії шляхів бере той мод, якого Vortex записав переможцем на цей шлях. Слоти `en`/`ru` і патч шрифтів лишаються як в звичайному ленгпаку (неофіційна UK). Якщо є синтез — додаються `UASoundPack.esp` і нестиснений `UASoundPack - Main.ba2`. `--no-apply-order` лишає абетковий merge, але все одно відсікає незадеплоєні моди.

## Група на сервері

Ключ групи: гра + шлях стейджа. Повторний sync оновлює ту саму групу.

Кожен мод і кожен master гри — окремий рядок. Нова версія (інший content hash) не затирає стару; у групи є `is_current` (як у релізів гри). Carry-over, TM і ленгпак за замовчуванням лише на поточні версії. Попередні лишаються в архіві — у списку модів під спойлером, з версією в назві.

Carry-over і ленгпак лише всередині групи. TM читає всю базу, пише тільки в групу.

У веб-UI на сторінці Моди джерело **Локальні імпорти** не показує Vortex-джоби. Вони лише в групі `Vortex · …`. Редактор той самий.

## Версії гри

Офіційні ESM з `Game\Data`, яких немає в стейджі, збираються в `vortex_game_releases`. Лейбл — ProductVersion з `Fallout4.exe`. Новий патч = новий реліз; попередній лишається для diff.

```text
npm run vortex:sync -- --staging ... --game-dir ... --channel game
```

## Токен

Якщо на сервері задано `TRANSYNTH_CLI_TOKEN`, CLI має передати той самий `--token` або змінну середовища. GET-ендпоінти (список груп) лишаються відкритими для UI.

Після зміни схеми: `npm run db:init`.
