## Навіщо потрібен re-import?

Моди регулярно оновлюються: автор може виправляти баги, додавати контент або перебалансовувати діалоги.
Коли ви імпортуєте нову версію, вже виконаний переклад не повинен пропасти.

Pipeline виявляє, що в базі вже існує старіша версія того самого мода, і пропонує **carry over** перекладів із попередньої версії у нову.

---

## Як працює diff

Порівняння двох версій іде за **FormID + field path**.

Для кожного рядка нової версії інструмент шукає відповідник у старій версії і порівнює source text.

Можливі результати:

- **Unchanged** — source text ідентичний, переклад можна безпечно переносити;
- **Changed** — source text змінився, переклад потребує рев’ю;
- **Added** — нового рядка не було в старій версії;
- **Removed** — рядок був у старій версії, але відсутній у новій.

## Сторінка Diff

Перейдіть у **Diff** через верхню навігацію (`/diff`).

Якщо поточний фільтр не дає жодного рядка, сторінка тепер показує action-first empty state з прямими next steps:

- **Show all changes** — скидає фільтр до `all`
- **Open current game hub** або каталог ігор, якщо game context ще не збережено

### Вибір двох версій

Сторінка містить два dropdown-и:

- **New Version** — щойно імпортована версія;
- **Old Version** — попередня версія, для якої у вас вже були переклади.

Обидва списки містять усі моди з бази, тому порівнювати можна будь-які два імпортовані моди, навіть якщо назви не збігаються буквально.

Якщо ви відкрили Diff із [ReimportModal](#reimportmodal) або з кнопки **Update Mod**, обидва ID уже передаються в URL (`?newModId=X&oldModId=Y`), і порівняння запускається автоматично.

Інакше виберіть моди вручну і натисніть **Compare**.

### Читання diff-таблиці

Після запуску порівняння зверху показується summary bar з кольоровими chips і кількістю рядків у кожній категорії.
Натискання на chip, крім `Unchanged`, фільтрує таблицю до відповідної категорії.

Колонки таблиці:

| Колонка         | Вміст                                          |
| --------------- | ---------------------------------------------- |
| **Change**      | Бейдж `added`, `removed` або `changed`         |
| **FormID**      | 8-значний hex FormID                           |
| **Type**        | Record signature (`NPC_`, `WEAP`, `DIAL` тощо) |
| **Source EN**   | Вихідний текст у цій версії                    |
| **Translation** | Наявний переклад з одного з боків або `—`      |
| **Status**      | Поточний статус перекладу                      |

Важливо: **Unchanged** рядки в таблиці не показуються — вони лише враховуються в summary chip `Unchanged: N`.

### Типи змін

| Бейдж         | Колір    | Значення                                         |
| ------------- | -------- | ------------------------------------------------ |
| **Added**     | Зелений  | Новий рядок у новій версії мода                  |
| **Removed**   | Червоний | Рядок зник у новій версії                        |
| **Changed**   | Жовтий   | Вихідний текст змінився, переклад може застаріти |
| **Unchanged** | Сірий    | Текст не змінився, перенос безпечний             |

## Перенесення перекладів

Після перегляду diff натисніть **Carry Over**, щоб скопіювати переклади зі старої версії в нову.

Поведінка така:

| Ситуація                   | Результат                                                     |
| -------------------------- | ------------------------------------------------------------- |
| **Unchanged** source text  | Переклад копіюється з тим самим статусом                      |
| **Changed** source text    | Старий переклад копіюється, але статус примусово стає `draft` |
| **Added**                  | Переклад не переноситься, рядок лишається порожнім            |
| Уже перекладений у new mod | Carry-over його не перезаписує                                |

Після завершення з’являється summary:

```text
Carried: 820 · Needs review: 43 · Skipped: 12
```

- **Carried** — незмінені рядки, перенесені з оригінальним статусом;
- **Needs review** — змінені рядки, перенесені як `draft`;
- **Skipped** — уже перекладені або такі, для яких немає коректного переносу.

Якщо є рядки, що потребують рев’ю, поряд з’являється посилання **Open in Editor (N drafts)**, яке відкриває новий мод із фільтром `status=draft`.

## Передрелізний чекліст

Після завантаження порівняння сторінка Diff тепер показує **передрелізний чекліст**.
Він тримає post-import workflow на одному екрані й показує поточний стан нової версії мода:

- **Coverage** — скільки рядків перекладено відносно загальної кількості
- **Drafts** — скільки рядків ще потребують ручного рев’ю після carry-over
- **QA issues** — скільки активних QA-блокерів лишається відкритими

Чекліст відстежує такі кроки:

1. Порівняння виконано
2. Carry-over запущено
3. Чернетки перевірено
4. QA-проблеми виправлено
5. Покриття перекладу завершено
6. Редактор відкрито для фінального експорту

Коли якийсь крок ще не завершений, чекліст дає прямі next-action переходи:

- **Review drafts** → відкриває редактор нового мода з `?status=draft`
- **Fix QA issues** → відкриває редактор нового мода з `?qaOnly=1`
- **Continue translating in editor** → відкриває редактор без фільтрів
- **Open editor for export** → повертає до toolbar редактора, коли чекліст уже чистий

Чекліст також містить блок **Recent handoff activity** для вибраного мода.
У ньому показуються останні дії з audit log, що стосуються саме цього мода,
а посилання **Open full activity log** відкриває **Settings → Activity** вже
з попередньо застосованим фільтром поточного мода.

## ReimportModal

Якщо ви імпортуєте мод, для якого в базі вже є старіша версія, інструмент автоматично показує **ReimportModal**.

Він пропонує:

1. підтвердити, що новий файл є оновленням вже відомого мода;
2. вибрати, чи переходити одразу у workflow переносу перекладів.

Модальне вікно показує список усіх попередніх версій цього мода з такими даними:

- назва мода;
- дата імпорту;
- загальна кількість рядків;
- відсоток завершення перекладу.

Якщо стара версія лише одна, вона вибирається автоматично.

Дії:

| Кнопка        | Дія                                                           |
| ------------- | ------------------------------------------------------------- |
| **Open Diff** | Відкриває `/diff?newModId=X&oldModId=Y` і запускає порівняння |
| **Skip**      | Закриває modal без переносу                                   |

Також modal можна закрити через `✕` або кліком поза ним. Це безпечно: diff workflow завжди можна запустити пізніше вручну.

## Що робити після повторного імпорту

Після carry-over:

1. Спочатку подивіться на **передрелізний чекліст** на сторінці Diff, щоб одразу побачити блокери.
2. Відкрийте нову версію в редакторі.
3. Відфільтруйте `Status = Draft`, щоб знайти рядки зі зміненим source text.
4. Перевірте і поправте кожен такий переклад.
5. Запустіть TM waterfall, щоб упіймати додаткові збіги з інших модів.
6. Перевірте QA, щоб знайти проблеми з placeholders, довжиною і термінами.
7. Поверніться до toolbar редактора, щоб експортувати STRINGS, BA2 або ZIP, коли чекліст чистий.

---

## Поради

- Завжди робіть diff **до** видалення старої версії мода з бази.
- Насамперед фокусуйтеся на категорії **Changed** — саме там потрібна ручна перевірка.
- `Unchanged` рядки зберігають свій початковий статус, тож повторне approve не потрібне.
- Після carry-over використовуйте пряме посилання **Open in Editor**, якщо воно з’явилося.
- Обов’язково запускайте QA після переносу перекладів зі змінених source strings.
