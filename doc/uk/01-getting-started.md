## Вимоги

- **Рекомендований шлях:** Docker Desktop з Docker Compose.
- **Локальний runtime:** практичний мінімум — Node.js 20+; Node.js 24 відповідає Docker-образу цього проєкту.
- **Менеджер пакетів:** npm (у репозиторії вже є `package.json` / `package-lock.json`; pnpm не потрібен).
- **База даних:** PostgreSQL 15+ для локального встановлення. Docker-стек використовує `postgres:17-alpine`.
- **Операційні системи:** Windows, macOS і Linux підходять для вебзастосунку. Якщо ви паралельно працюєте з інструментами для модингу Fallout, найпрактичніший хост — Windows.

## Варіант A: Docker (рекомендовано)

Docker автоматично бере на себе Node.js, PostgreSQL і всі залежності.
Це найпростіший спосіб старту.

1. Встановіть Docker Desktop.
2. Клонуйте репозиторій.
3. Скопіюйте `.env.example` у `.env` у корені проєкту.
4. Перевірте параметри в `.env`.
   Типові параметри бази вже вказують на локальний PostgreSQL, створений Docker Compose:
   - `POSTGRES_USER=localizer`
   - `POSTGRES_PASSWORD=localizer`
   - `POSTGRES_DB=localizer`
   - `DATABASE_URL=postgresql://localizer:localizer@localhost:5432/localizer`
5. Якщо ви використовуєте Ollama, залиште `LLM_PROVIDER=ollama` і вкажіть у `OLLAMA_MODEL` модель, яка вже встановлена у вашому Ollama.
6. Запустіть базу даних і вебсервер:

```bash
docker compose up -d db web
```

7. Ініціалізуйте схему бази даних:

```bash
docker compose run --rm cli npm run db:init
```

8. Відкрийте `http://localhost:3000` у браузері.

Примітки:

- Сервіс `web` віддає і Fastify API, і зібраний React UI на порту `3000`.
- Сервіс `cli` — одноразовий контейнер для команд на кшталт `db:init`, перекладу, імпорту та експорту.
- Щоб зупинити стек, виконайте `docker compose down`.

## Варіант B: Локальний Node.js

Використовуйте цей варіант, якщо хочете запускати backend і frontend напряму.

1. Встановіть Node.js 20+ і PostgreSQL 15+.
2. Клонуйте репозиторій.
3. Встановіть backend-залежності:

```bash
npm install
```

4. Встановіть frontend-залежності:

```bash
npm --prefix web-ui install
```

5. Скопіюйте `.env.example` у `.env` і вкажіть у `DATABASE_URL` вашу локальну PostgreSQL-базу.
6. Створіть базу даних, якщо її ще немає, і ініціалізуйте схему:

```bash
npm run db:init
```

7. Запустіть backend API в одному терміналі:

```bash
npm run web:dev
```

8. Запустіть frontend Vite dev server у другому терміналі:

```bash
npm --prefix web-ui run dev
```

9. Відкрийте `http://localhost:5173` у браузері.

Важливо:

- У локальній розробці React UI працює на порту `5173` і проксіює API-запити на `http://localhost:3000`.
- Скрипт `npm run dev` — це змішаний локально/Docker сценарій: він піднімає базу командою `docker compose up db`, а потім запускає backend локально на `3000` і frontend локально на `5173`.

## Перший запуск: створення бази даних

Перед першим використанням схему бази даних потрібно ініціалізувати.
Це одноразова операція.

Запустіть одну з команд:

```bash
npm run db:init
```

або, через Docker:

```bash
docker compose run --rm cli npm run db:init
```

Що це робить:

- Зчитує `sql/schema.sql` і застосовує його до бази з `DATABASE_URL`.
- Створює основні таблиці та індекси для модів, записів, вихідних рядків, перекладів, історії перекладів, термінів глосарію, джоб імпорту, QA-проблем, QA-правил, сесій, користувачів, журналу активності та кешу перекладів.
- Додає bootstrap-рядок користувача `admin`, якщо його ще немає.

Чого це не робить:

- Не сідує жодних стандартних QA-правил. Таблиця `qa_rules` створюється порожньою.
- Не скидає і не очищає базу.

Примітки з безпеки:

- Схема написана ідемпотентно: використовуються `CREATE IF NOT EXISTS`, `ALTER ... IF NOT EXISTS` і `ON CONFLICT DO NOTHING`, тому команду безпечно запускати повторно під час звичайного налаштування.
- Хоч це і не destructive reset, команда все одно змінює ту базу, на яку вказує `DATABASE_URL`. Перед запуском на спільній або важливій БД ще раз перевірте ціль.
- Placeholder-рядок `admin` створюється схемою. При старті вебсервера застосунок дбає про те, щоб у цього акаунта був реальний password hash.

## Відкриття Web UI

Використовуйте URL, що відповідає вашому режиму запуску:

- **Docker:** `http://localhost:3000`
- **Локальний frontend dev server:** `http://localhost:5173`

Після першого успішного запуску застосунок відкривається на сторінці **Mods** (`/`).
Це головна стартова сторінка для перегляду імпортованих модів і відкриття редактора.

У верхній панелі застосунку також видно:

- окремий пункт **Home** у головній навігації
- badge поточного workspace **Game**, який зберігається з останнього відкритого game-scoped route
- поточну пару робочих мов **Content** (`SRC → TGT`), синхронізовану з source/target мовами з Settings

Коли ви відкриваєте workspace гри (`/games/:gameId`), **Game Hub** працює як стартова workflow-сторінка з окремими картками для:

- **Import**
- **Translate**
- **Quality**
- **Release**

а також із додатковою карткою **Discover** для перегляду NexusMods.

У блоці **Release** також є явна двокрокова схема:

1. **Open Diff** для порівняння оновлених версій і carry-over перекладів.
2. **Open Imported Mods** для повернення в editor і експорту STRINGS, BA2 або ZIP після review та QA.

У game-scoped браузері Nexus (`/games/:gameId/nexus`) порожній результат пошуку містить прямі дії: очищення пошуку і повернення в хаб гри.

## Вхід і багатокористувацький режим

Інструмент може працювати у **single-user mode** (вхід не потрібен, типовий режим) або в **multi-user mode** (акаунти, ролі, аудит).

Типово застосунок працює у **single-user mode**:

- Екран входу не показується.
- Backend автоматично підставляє особу адміністратора за замовчуванням.
- Керування користувачами вимкнене.

Щоб увімкнути **multi-user mode**, додайте в `.env` і перезапустіть backend:

```bash
MULTI_USER=true
```

Що змінюється після увімкнення multi-user mode:

- З’являється сторінка входу.
- Сесії зберігаються в базі даних і автентифікуються через HTTP-only cookie.
- Активується рольова модель доступу.
- Стає доступною сторінка **Users**, де адміністратори можуть створювати акаунти, вимикати користувачів і керувати паролями.

У multi-user mode в app shell також з’являється невеликий role-aware shortcut badge поруч із badge поточної Game та Content:

- **Reviewers** отримують прямий shortcut до **Review Queue**.
- **Admins** отримують прямий shortcut до **Users**.
- **Translators** бачать shell, сфокусований на перекладацьких поверхнях без зайвих адмінських посилань.

Bootstrap-акаунт за замовчуванням:

- **Username:** `admin`
- **Password:** `admin`

Після першого входу в багатокористувацькому режимі змініть цей пароль одразу.
Застосунок підтримує зміну паролів користувачів у multi-user mode, а адміністратори можуть керувати іншими акаунтами зі сторінки Users.

Про ролі, права і командний workflow дивіться [Команда та користувачі](16-team-and-users.md).
