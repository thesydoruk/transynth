## Що таке Translation Memory?

Translation Memory — це база даних попередньо перекладених пар рядків:
`(source text) → (translation)`.

Коли ви імпортуєте новий мод, конвеєр звіряє кожен вихідний рядок із TM.
Якщо знаходиться збіг, переклад може бути підставлений автоматично, щоб вам не доводилося знову перекладати ідентичний або майже ідентичний текст.

TM поступово зростає в міру того, як ви перекладаєте більше модів.

Якщо сторінка Glossary ще порожня, UI показує коротку підказку заповнити повторювані терміни проєкту перед великими імпортами або LLM-прогонами.

## Методи автозастосування

Автозастосування перевикористовує наявний переклад лише за **точного або
anchor-збігу**. Методи пробуються від найточнішого; перемагає перший збіг.

> **Чому лише точні збіги?** Наближені евристики (trigram fuzzy,
> punct-norm, перенесення чисел, phrase segmentation, reverse TM) вилучено
> з автозастосування. Для неідентичних рядків конвеєр LLM + RAG дає кращу
> якість, тож TM-автозастосування тепер обмежене безкоштовним, миттєвим і
> безвтратним перевикористанням ідентичного тексту. Для неідентичних рядків
> див. вкладку [RAG-приклади](#вкладка-rag-приклади-у-detail-panel), яка
> показує референсні переклади тим самим пошуком, що живить LLM.

### 1. Anchor Match

Точний збіг за **FormID + field path** між різними модами (confidence: `0.95`).
Це найнадійніший спосіб, бо він фактично знаходить той самий логічний запис, який був замінений або перевизначений в іншій версії мода.

Anchor matches з’являються, коли:

- мод оновили і повторно імпортували (той самий FormID, але інший мод-запис);
- patch або compatibility mod перевизначає запис із базового мода;
- DLC-запис присутній і в DLC ESM, і в сторонньому patch-файлі.

Backend-запит матчить `records.formid_hex + records.path`, виключає поточний мод і вибирає переклад із найкращим пріоритетом статусу:
`reviewed > human > tm > auto > draft`.

### 2. EDID Match

Збіг за **EDID + field path**, без урахування FormID (confidence: `0.85`).
Корисно, коли мод змінює FormID між версіями, але зберігає той самий Editor ID.

Приклад: запис із `EDID = FortHagen_Terminal` і path `TERM.FULL` у версії мода 1.0 в 1.1 отримує новий FormID. Оскільки EDID стабільний, pipeline знаходить наявний переклад через `records.edid + records.path`, хоча FormID змінився.

EDID matching також має fallback до EDID-only варіанта без фільтра path і бере переклад із найкращим статусом.

### 3. Text-Norm Match

Збіг за **нормалізованим вихідним текстом** (confidence: `0.75`).
Нормалізація:

- згортає всі послідовності whitespace у один пробіл;
- переводить текст у lowercase;
- замінює всі ігрові placeholders на `¤PH¤`;
- замінює кожне число на `¤NUM¤`.

Приклад: рядки `"Hello, World!"` і `"Hello, World!"` обидва нормалізуються в `"hello, world!"` і вважаються збігом, навіть якщо пробіли в оригіналі відрізняються.

Оскільки числа замінюються на етапі нормалізації, два рядки, що відрізняються лише числовими значеннями, теж матимуть однаковий `text_norm` і вважатимуться збігом. Автозастосування тоді **переносить числа** з поточного source у знайдений переклад (метод `numeric`, confidence `0.72`). Якщо перенос небезпечний (інша кількість чисел або числа відсутні в перекладі) — збіг пропускається, а не копіюється з чужими числами.

## Автозастосування TM після імпорту

Під час імпорту мода pipeline може автоматично прогнати методи точного/anchor-збігу для кожного рядка і заповнити переклади там, де є збіг.

Такі переклади отримують статус **TM**.
Після цього ви можете перевірити й підтвердити їх у редакторі.

Практична примітка для поточного web workflow: основна робота з TM у UI відбувається як окрема дія в редакторі через **Apply TM**.

## Ручне застосування TM-підказок

Якщо рядок не отримав авто-переклад, ви все одно можете використати підказку з TM через Detail Panel:

1. Виберіть рядок у таблиці.
2. Відкрийте вкладку **RAG-приклади**.
3. Натисніть **Apply** біля потрібної підказки, щоб скопіювати її в translation field.
4. За потреби відредагуйте текст і збережіть через **Ctrl+S**.

Також ви можете запустити повторний TM-matching для всього мода або для відфільтрованого набору рядків через пакетну дію **Apply TM**.

## Вкладка RAG-приклади у Detail Panel

Вкладка **RAG-приклади** показує до **10** референсних перекладів для поточного рядка. Її живить **той самий гібридний RAG-пошук, що й LLM** (`findReferenceExamples`): TM-збіги (exact, numeric, punct_norm, fuzzy) плюс семантична подібність pgvector (`embedding`). Окремого запиту-підказок більше немає — панель і LLM мають одне джерело істини.

Прийнятні лише переклади `reviewed` / `human` (RAG-індекс). Результати ранжуються за комбінованою оцінкою (`method_weight × similarity`). Якщо RAG недоступний (наприклад, не встановлено pgvector), панель просто не показує прикладів, а не падає з помилкою.

| Колонка      | Опис                                                  |
| ------------ | ----------------------------------------------------- |
| Бейдж збігу  | Якість збігу у відсотках (0–100%)                     |
| Method label | `exact`, `numeric`, `punct`, `semantic` або `fuzzy`   |
| Translation  | Референсний переклад (наведіть, щоб побачити джерело) |
| Apply        | Копіює референсний переклад у translation field       |

Натискання **Apply** лише переносить текст у textarea.
Автозбереження не відбувається: статус лишається без змін, поки ви не збережете переклад через **Ctrl+S** або **Ctrl+Enter**.

## Як переклади потрапляють у TM

Кожного разу, коли ви зберігаєте переклад, він автоматично потрапляє в TM.
Це стосується будь-якого статусу: `draft`, `reviewed`, `human`, `tm`, `fuzzy` або `auto`.

Так само TM поповнюється імпортованими перекладами з:

- EET-файлів;
- CSV-файлів.

Політика дедуплікації:

- таблиця `translations` зберігає **один переклад на пару (source string, target language)**;
- нове збереження для того самого рядка замінює старий запис;
- накопичення кількох паралельних перекладів для одного рядка не відбувається.

Оскільки багато рядків можуть мати спільний `text_norm`, збереження одного перекладу може автоматично поширитися на інші рядки з тим самим normalized source text, якщо в них ще немає `draft`, `reviewed` або `human` перекладу. Для рядків із іншими числами переклад адаптується (number transplant); небезпечні кандидати пропускаються. Таке поширення виставляє статус **`tm`**.

CSV imports користуються тим самим шляхом `upsertTranslation`, тому поводяться так само.
