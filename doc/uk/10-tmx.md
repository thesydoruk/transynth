## Що таке TMX?

**TMX 1.4b** — це відкритий XML-стандарт для обміну даними Translation Memory між різними перекладацькими інструментами.
Практично всі професійні CAT-системи вміють імпортувати й експортувати TMX.

TMX-файл містить translation units такого вигляду:

```xml
<tu>
  <tuv xml:lang="en"><seg>Take care, wanderer.</seg></tuv>
  <tuv xml:lang="uk"><seg>Бережись, мандрівнику.</seg></tuv>
</tu>
```

---

## TMX і release workflow

TMX — це **surface для обслуговування translation memory**, а не фінальна release-поверхня для оновленого мода.

Використовуйте **TMX**, коли потрібно:

- поділитися translation memory з іншим CAT-інструментом або колегою;
- зробити резервну копію поточної translation memory;
- початково наповнити новий проєкт уже готовими перекладами.

Використовуйте **Diff + експорт із Mod Editor**, коли потрібно:

- порівняти оновлену версію мода з попередньою;
- перенести старі переклади в нову версію;
- перевірити чернетки та прибрати QA-блокери;
- експортувати STRINGS, BA2 або ZIP як фактичний release package.

## Експорт TMX

Перейдіть на сторінку **TMX** у верхній навігації (`/tmx`) і використайте секцію **Export**.

У формі є два головні елементи керування:

- **Mod (optional)** — випадаючий список імпортованих модів; якщо лишити `All mods`, експортується вся TM;
- **Target language** — мова перекладів, які потрібно вигрузити.

Після натискання **Export TMX** сервер згенерує файл і браузер одразу його завантажить.

Іменування залежить від scope:

- `tm_all_{srcLang}_{tgtLang}.tmx` для глобального експорту;
- `tm_mod{id}_{srcLang}_{tgtLang}.tmx` для одного мода.

Приклади:

- `tm_all_en_uk.tmx`
- `tm_mod42_en_uk.tmx`

Scope експорту:

- **All mods** — усі збережені переклади з бази;
- **Single mod** — лише переклади конкретного проєкту.

## Імпорт TMX

Секція **Import** на сторінці TMX дозволяє завантажити файл із зовнішнього інструмента.

Елементи форми:

- **Match against** — або `All mods (global)`, або конкретний мод;
- **TMX file** — file picker для `.tmx` або `.xml`.

Після натискання **Import TMX** файл завантажується й обробляється на сервері.
Під час виконання кнопка показує стан `Importing…`.

Після завершення з’являється summary:

```text
Parsed: 1 240 · Imported: 820 · Skipped: 420
```

Пояснення:

- **Parsed** — скільки translation units прочитано з файлу;
- **Imported** — скільки units збіглися з наявними source strings і створили нові переклади;
- **Skipped** — скільки units не знайшли відповідного рядка або були відкинуті політикою конфліктів.

Політика конфліктів:

- якщо рядок уже має `reviewed` або `human` переклад, TMX-імпорт його не перезаписує;
- якщо рядок має нижчоякісний статус (`draft`, `tm`, `fuzzy`, `auto`, `rejected`), він теж не перезаписується;
- тобто поточна реалізація **ніколи не overwrite-ить уже наявний переклад**.

Імпортовані переклади отримують:

- `status = 'tm'`
- `provenance = 'tmx_import'`

## Сумісність

TMX 1.4b, який генерує цей інструмент, сумісний із:

| Інструмент        | Примітка                                        |
| ----------------- | ----------------------------------------------- |
| SDL Trados Studio | Імпорт/експорт через Translation Memories panel |
| memoQ             | Import через Translation Memories → Import      |
| OmegaT            | Досить покласти `.tmx` у папку `tm/` проєкту    |
| Wordfast          | Імпорт через TM Manager                         |

Експорт використовує стандартне UTF-8, `xml:lang` в елементах `<tuv>` і не містить vendor-specific extensions, тому додаткового mapping не потрібно.

---

## Типові сценарії використання

- **Командна співпраця** — перекладач у OmegaT може імпортувати ваш TMX як reference, а потім віддати свій TMX назад для merge.
- **Резервне копіювання і міграція** — повний експорт TM перед перенесенням на іншу машину.
- **Початкове наповнення TM** — якщо у вас вже є переклади з іншого проєкту, конвертуйте їх у TMX і імпортуйте для швидкого старту.
