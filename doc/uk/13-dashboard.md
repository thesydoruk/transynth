## Загальний прогрес

У верхній частині сторінки є **чотири summary cards** з агрегованими числами по всіх модах:

| Картка         | Що показує                                                        |
| -------------- | ----------------------------------------------------------------- |
| **Strings**    | Загальну кількість імпортованих translatable strings              |
| **Translated** | Скільки рядків мають будь-який переклад, плюс відсоток            |
| **Approved**   | Скільки рядків мають статус `human` або `reviewed`, плюс відсоток |
| **QA Issues**  | Кількість активних QA-зауважень                                   |

Якщо QA issues більше нуля, картка виділяється червоним; якщо проблем немає — зеленим.

Нижче розташована таблиця по модах. Для кожного мода показується горизонтальний progress bar.
Коли мод доходить до 100%, смуга стає зеленою, інакше вона синя.

Якщо імпортовано кілька модів, унизу з’являється **totals footer row** з сумою по всіх проєктах.

## Прогрес за GRUP

Основна таблиця per-mod показує імпортовані моди й розбивку за статусами перекладів:

| Колонка        | Що рахується                       |
| -------------- | ---------------------------------- |
| **Strings**    | Усі вихідні рядки                  |
| **Translated** | Рядки, що мають будь-який переклад |
| **%**          | Частка `Translated / Total`        |
| _(bar)_        | Візуальний progress bar            |
| **Approved**   | Статуси `human` + `reviewed`       |
| **Draft**      | Статус `draft`                     |
| **TM**         | Статуси `tm` + `fuzzy`             |
| **Auto**       | Статус `auto`                      |
| **QA**         | Кількість активних QA-проблем      |

Натисніть toggle **▸** біля рядка мода, щоб розгорнути **GRUP breakdown sub-table**.
Вона показує ті самі метрики, але вже по типах записів, щоб одразу бачити, де лишається найбільше роботи.

Назва мода в таблиці є посиланням і веде прямо в його редактор.

Чому деякі GRUPs мають більше рядків:

- `DIAL` / `INFO` — діалоги, зазвичай наймасивніший пласт тексту;
- `BOOK` — книги, записки та довгі читабельні тексти;
- `NPC_`, `WEAP`, `ARMO` — назви й короткі описи;
- `CONT`, `MISC` — контейнери, предмети, короткі описи;
- `MCM`, `PEX` — текст із меню конфігурації та Papyrus scripts.

## QA Summary

Під summary cards є секція **QA breakdown**, яка показується лише тоді, коли активні QA issues взагалі існують.

Вона виводить типи проблем, для яких є хоча б один випадок, разом із mini bar chart і кількістю:

| Тип проблеми              | Колір        |
| ------------------------- | ------------ |
| `placeholder mismatch`    | Червоний     |
| `empty translation`       | Червоний     |
| `forbidden chars`         | Червоний     |
| `same as source`          | Помаранчевий |
| `length delta`            | Помаранчевий |
| `glossary violation`      | Помаранчевий |
| `duplicate inconsistency` | Бірюзовий    |

Довжина смуги пропорційна частці цього типу серед усіх активних QA-проблем.

У таблиці модів значення в колонці **QA** клікабельне, якщо воно
більше за `0`. Клік відкриває редактор відповідного мода з увімкненим
фільтром **Лише QA** (`qaOnly=1`), щоб одразу перейти до рядків з
активними QA-проблемами.

## Як використовувати статистику для планування роботи

- Якщо треба швидко знайти найбільші зони незавершеної роботи, розгорніть GRUP breakdown і подивіться, де найбільший розрив між `Strings` і `Translated`.
- Високий `TM` і низький `Approved` означає, що в моді багато автоматично підставлених перекладів, які ще не підтверджені. Це зручний кандидат для швидкого review-pass.
- Високий `Auto` означає, що LLM уже попрацювала, і пріоритет — QA та ручне рев’ю.
- Відсоток і progress bar зручні як milestone-метрика для команди або звітності.

## Панель стану та операцій

Окрема сторінка **Стан** (маршрут: `/ops`, посилання «Стан» у навігації) забезпечує
моніторинг сервера та фонових процесів у реальному часі.

### Система

П’ять карток у верхній частині:

| Картка         | Опис                                           |
| -------------- | ---------------------------------------------- |
| **Час роботи** | Скільки часу працює сервер (напр. `2d 5h 12m`) |
| **Node.js**    | Версія середовища виконання (напр. `v20.11.0`) |
| **Heap used**  | V8 heap-пам’ять, яка використовується          |
| **RSS**        | Resident Set Size — загальна пам’ять процесу   |
| **База даних** | Зелене «Підключено» / червоне «Недоступна»     |

### Завдання імпорту

Таблиця з **30 останніми** завданнями імпорту з усіх трьох джерел
(EET, CSV, Mod), відсортованих за новизною. Кожен рядок показує:

- **Тип** — бейдж: `EET`, `CSV` або `MOD`.
- **Файл** — назва завантаженого файлу.
- **Статус** — кольоровий бейдж (зелений = завершено, синій = виконується,
  червоний = помилка, помаранчевий = пауза).
- **Прогрес** — лічильник `імпортовано / всього (%)`.
- **Помилка** — повідомлення про помилку для невдалих завдань.
- **Оновлено** — час останньої зміни статусу.

### LLM / Автопереклад

Дві картки:

| Картка              | Значення                               |
| ------------------- | -------------------------------------- |
| **Записів кешу**    | Кількість рядків у кеші LLM-перекладів |
| **Автоперекладено** | Загальна кількість перекладів від LLM  |

Нижче — таблиця **по-модельної розбивки**, що показує, скільки
рядків переклала кожна модель (напр. `openai:gpt-4o`, `vllm:Meta-Llama-3-8B-Instruct`).

### База даних

Одна картка із **загальним розміром БД** (напр. `42 MB`), потім таблиця
з оцінкою кількості рядків і дискового розміру кожної основної таблиці.
Корисно для знаходження неочікувано великих таблиць та планування резервних копій.

Сторінка автоматично оновлюється кожні 30 секунд.
