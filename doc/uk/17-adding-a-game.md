# Додавання гри

Гра — це **плагін**: одна тека в `src/games/`, яка реалізує контракт із
`src/games/contract`, плюс один рядок реєстрації в `src/games/index.ts`.

Поза цією текою не змінюється нічого. У конвеєрі немає жодного `switch (game)`,
жодної мапи `Record<GameId, …>`, яку треба доповнювати, і жодного порівняння
ідентифікатора гри з літералом у спільному коді — імпорт, експорт, озвучка,
промпти й редактор питають плагін.

---

## Два типи гри

**Титул на Creation Engine** (Fallout, Elder Scrolls) уже має весь конвеєр.
Додати такий — це _дескриптор_, а не код:

```ts
// src/games/creation-engine/titles/fallout.ts
export const fallout4: CreationEngineTitle = {
  id: 'fo4',
  catalogue: { name: 'Fallout 4', developer: '…', releaseYear: 2015, … },
  subrecords: compileSubrecordConfig(fo4Subrecords),  // де саме лежить текст
  recorddefs: compileRecorddefs([fo4Recorddefs]),     // у якій таблиці STRINGS
  archive: { kind: 'ba2', bsaVersion: 104 },
  strings: { lookupOrder: ['loose', 'ba2'], officialLocales: FO4_LOCALES },
  voice: { faceFxTitle: 'Fallout4', packLangpackVoiceIntoBa2: true },
  deployment: { officialMasters: [...], vortexId: 'fallout4', exeName: 'Fallout4.exe' },
  prompts: { … },
};
```

Реєструєте — і все:

```ts
// src/games/index.ts
registerGamePlugin(createCreationEnginePlugin(starfield));
```

**Будь-що інше** — інший рушій, інші формати — це власна тека плагіна.
`src/games/disco-elysium/` є робочим прикладом: гра на Unity без формату
плагінів, без архівів і без таблиць рядків, локалізація якої — тека з
gettext-каталогами `.po` та окремими `.wav`.

## Що оголошує плагін

| Адаптер      | Відповідає на питання                                                                            | Обов'язковий |
| ------------ | ------------------------------------------------------------------------------------------------ | ------------ |
| `catalogue`  | Назва, студія, рік, рушій, ідентифікатори NexusMods                                              | так          |
| `editor`     | Які вкладки, колонки й дії отримують моди цієї гри                                               | так          |
| `text`       | Розмітка, яку LLM має зберегти, зняття цензури, захищені ключові слова, який текст містить запис | так          |
| `prompts`    | Українські промпти, англійські блоки правил, глосарій, другий прохід                             | так          |
| `import`     | Який файл є якорем завантаження, який його обсяг, як його прочитати                              | так          |
| `export`     | Вміст ленгпака й повного ZIP мода                                                                | так          |
| `dialog`     | Хто говорить рядок, до кого, і чи фіксована стать протагоніста                                   | ні           |
| `voice`      | Як називаються, шукаються й синтезуються репліки                                                 | ні           |
| `deployment` | Майстри, порядок завантаження, id Vortex — для розгортання менеджером                            | ні           |

Пропустіть необов'язковий адаптер — і функція зникне без слідів: німа гра не
отримає вкладки Voice і голосових задач, гру, яку не розгортає жоден менеджер
модів, пропустить сканер Vortex, а гра без `dialog` матиме рядки без учасників —
і промпт прочитає це як «не репліка», а не як «репліка, чийого мовця ми
загубили».

`dialog` — єдиний адаптер, що дає SQL. І `participantsSql` (хто говорить рядок і
до кого), і `lineSpeakerSql` (що показує колонка мовця в сітці рядків) стають
гілками спільного lateral-join, тож кожен мусить обмежитися переданим
`gameList`: один запит може охоплювати моди різних ігор. `lineSpeakerSql`
необов'язковий і відповідає на ширше питання: для Creation Engine він покриває
ще й запис, який просто **називає** актора, бо перекладачеві потрібен його рід,
щоб відмінювати ім'я.

Тут же оголошується, чи стать протагоніста обирає гравець (`any`, усі титули
Bethesda), чи вона написана (Гаррі з Disco — чоловік) — це `playerGender`, бо
ховати рід написаного персонажа означає перекласти неправильно.
`isSpokenSignature` каже, які типи записів цієї гри є вимовленими репліками;
спільний код питає його замість перевірки на `INFO`.

## Покроково

1. **Створіть теку** `src/games/<гра>/` із `plugin.ts`, що експортує
   `GamePlugin`.

2. **Каталог і редактор.** Заповніть метадані плитки й скажіть, які екрани має
   показувати редактор. API віддає це браузеру, тож UI не змінюється — зокрема й
   перелік типів файлів у діалозі завантаження, який береться з
   `import.uploadExtensions`.

3. **Імпорт.** Реалізуйте три функції:
   - `selectAnchor(extractDir)` — до якого файлу всередині архіву прив'язується
     імпорт, або `null`, якщо в архіві немає нічого читабельного для цієї гри;
   - `describeAnchor(anchorPath, extractRoot)` — чи текст зовнішній і скільки
     записів очікувати;
   - `ingest(ctx)` — прочитати мод, записати записи й рядки, потім викликати
     спільний `finalizeModImport`. Перевіряйте `ctx.state.cancel` /
     `ctx.state.pause` між пакетами, щоб призупинена задача коректно
     відновлювалась.

4. **Експорт.** `collectLangpackEntries(ctx)` повертає окремі локалізовані
   файли; `exportFullModZip(ctx)` — увесь мод із застосованими перекладами. Гра,
   у якої обидві форми однакові, вказує на одну реалізацію.

5. **Озвучка, якщо гра озвучена.** Адаптер відповідає за іменування реплік,
   їх пошук, задачу синтезу на весь мод, синтез одного рядка й каталог для
   вкладки Voice.

6. **Промпти.** Український промпт перекладу й перевірки, англійські блоки
   правил і глосарій. Якщо текст гри не має нічого спільного зі спільними
   правилами (записи, рівні рідкісності, шаблони назв спорядження), поставте
   `english.useCommonRules: false` і дайте власні.

7. **Зареєструйте** гру в `src/games/index.ts`. Порядок реєстрації — це порядок
   у каталозі.

## Що перевіряється

`src/games/__tests__/registry.test.ts` перевіряє, що кожен зареєстрований плагін
має адаптери, які конвеєр викликає беззастережно, — тож недороблений плагін
завалює тести, а не перший імпорт.

Решту тестів кладіть поруч із плагіном, у
`src/games/<гра>/__tests__/`, як це зроблено для Disco Elysium.

---

## Правила, на яких тримається розкладка

- **Спільний код не називає ігор.** Якщо ви дописуєте `game === 'x'` поза
  `src/games/`, те, за чим ви розгалужуєтесь, має бути в контракті.
- **І не називає типів записів однієї гри.** `grup === 'TERM'` — та сама
  помилка в іншому вбранні: воно хибне для всіх ігор, крім однієї, тож решта
  тихо йде гілкою else. Питайте `text.recordKind(grup, field)`, а якщо
  потрібного розрізнення там немає — додайте новий вид. `src/formats/**` і
  модулі імпорту та запитів Bethesda — це домен самого рушія, вони лишають
  свій словник; `src/llm`, `src/utils`, `src/dialog` і воркер — ні, і це
  стереже тест.
- **Код, яким користується рівно один плагін, живе всередині нього.** Код, який
  ділять кілька, лежить у бібліотеках (`src/formats`, `src/import`, `src/voice`,
  `src/web/export`) і приймає явні параметри, а не ідентифікатор гри, який він
  сам тлумачить.
- **Шукайте плагіни через `src/games/registry`.** Цей модуль не імпортує жодного
  плагіна, тож циклу імпортів не буде. Сам `src/games` імпортують лише точки
  входу — HTTP-сервер, воркер, кожен скрипт і setup-файл Jest, — і саме цей
  імпорт виконує реєстрацію.
