# Changelog

## Unreleased

Vortex, from a command somebody has to remember to a process that watches:

- **A resident agent on the Vortex machine.** `npm run vortex:agent` watches the staging folder and the load-order files, waits for Vortex to finish installing and deploying, hashes the inventory through a size+mtime cache (the game's multi-gigabyte archives are read once), uploads only what changed, runs import, carry-over and TM — which now reaches the reference base, so official ESMs, DLC and known mods come back reviewed — and sends the server the current load order. A change to the order alone sends just the order. A finished langpack is downloaded as `.part` into Vortex's downloads folder and renamed into place, so Vortex offers it on the Downloads tab; nothing is ever written into staging or deleted from downloads. The agent never starts LLM translate, verify, skip-detect, gender-detect, voice or export: `autoStages` parses to `import`, `carry` or `tm` and nothing higher. `--init` writes the config, `--dry-run` scans without a server call, `--once` is one tick for a scheduled task; state, cache and journal live in `%LOCALAPPDATA%\Transynth\vortex-agent`, failures back off from one minute to thirty.
- **Stages as buttons, run as the editor's own jobs.** `verify`, `skip`, `gender` and `voice` join the stage list after `llm`; `install` is retired. A fan-out stage enqueues, for one mod at a time, the same per-mod job the editor starts, so LLM and TTS keep seeing one job each and the editor keeps its badges and stop buttons; `POST /api/vortex/groups/:id/stage/:stage` refuses to start while a run is active or when the host a stage needs is down (409 with the service name), `POST /api/vortex/sync/:runId/stop` stops the run and its per-mod jobs, `GET /api/vortex/sync/:runId` carries live per-mod progress.
- **A Vortex page.** `/games/<game>/vortex`: the agent's heartbeat (machine, last seen, what it waits for, last error, delivered langpack), the stage buttons disabled while a run is active or a host is down, the live run with per-mod jobs and Stop, run history, the newest langpack to download. A card on the game hub leads to it.
- **A run a deploy interrupts is closed, not left running.** The worker, stopped mid-import, left the run `running` and the group refusing every stage with 409 until somebody edited the row. On start the worker now fails every unfinished Vortex run whose job BullMQ no longer runs, and a job BullMQ fails as stalled writes its reason into the run; a run whose job is still queued or active is left alone.
- **The voice BA2 is one the game can read.** Entries were hashed with a standard CRC-32 and carried zeroed flags; the game finds a file by those hashes and refused to start with `UASoundPack - Main.ba2` active. The writer now hashes as Archive2 does (CRC-32 from a zero register, no final xor) and writes the flags and align values every shipped archive carries. A langpack exported before this needs exporting again.
- **The agent does not sync its own output.** Installing the langpack through Vortex made the agent upload it as a mod (4 GB of our voice archive, a mod with nothing to translate) and, because Vortex deploys the langpack's strings into Data, see the base game as changed and re-import it. A staging folder named like a delivered langpack, or holding the dummy voice plugin, is skipped; files that `vortex.deployment.json` in Data attributes to a mod do not count towards a game unit's hash.
- **Server side.** `vortex_agents` (one heartbeat row per group and machine), `vortex_groups.export_order_json`, `vortex_sync_runs.stage` / `started_by`; `POST /api/vortex/agent/heartbeat`, `POST /api/vortex/groups/:id/export-order`, `GET /api/vortex/groups/:id/state` and `/runs`. The CLI token gates only the agent's and the CLI's writes; the page's buttons are as open as the rest of the app.

See [Vortex](eng/16-vortex-sync.md). Run `npm run db:init` after pulling.

Cutscene videos, the inventory first:

- **The agent registers the game's videos.** With `"videos": true` in its config the agent lists the Bink files of the game's video folder (a plugin declares it through `media`; Fallout 4's twelve films with narration, `Data/Video/*.bk2`), fingerprints each by size, mtime and its first MiB, asks `ffprobe` for the audio tracks — Bink keeps one per language, the id the game picks by — and uploads the lowest (or `videoSourceTrack`) decoded to 48 kHz stereo WAV with `ffmpeg`. A video the server already holds with the same fingerprint is skipped; a swapped file is re-registered and its old audio and dub forgotten. The scan runs once per `fullScanEveryMin` and never holds up the mod sync.
- **Server side.** `video_assets` and `video_segments`; `GET /api/video/:game`, `POST /api/video/:game/assets` and `PUT /api/video/:game/:id/audio` (the agent's writes, under the CLI token), `GET /api/video/:game/:id/audio/:kind`. A Video page (`/games/<game>/video`) lists the videos with their length, tracks, state and a player for the uploaded narration; a card on the hub leads to it.
- **Separation, and the narration as a mod.** _Separate & transcribe_ on the Video page starts `video-separate` — the first job on the `separate` queue — which hands the uploaded track to audio-intel's batch lane, keeps the speech and background tracks it returns next to the source, and merges the timed, speaker-labelled transcript into phrases (one speaker, pauses under 0.4 s, at most 12 s). The phrases become the records of one mod per game, `Video` (origin `video`, `INFO\NAM1` so the dialogue prompt applies), one record per phrase keyed by the video and its index; a phrase whose text did not change keeps its string and so its reviewed translation across a second run. TM, LLM translate, verify and the editor then work on the narration as on any mod. `POST /api/video/:game/:id/separate` (409 while busy or with no healthy `separate` / `asr` host), `GET /api/video-separate/:jobId`, `GET /api/video/:game/:id/segments`; the audio route takes `?from=&to=` to play one phrase. The transcript parser now keeps audio-intel's `speaker_id`.
- **The dub.** _Dub_ starts `video-dub` on the `tts` queue: for every translated phrase a take cloned from the narration itself — the phrase's own slice of the speech track first, so Fish Speech's `match_timing` fits the take to the actor's slot, then the nearest phrases of the same speaker up to the preferred reference length — under the project's retry policy. A take still longer than the time to the next phrase is sped up by at most 15 % (`atempo`); what cannot fit is marked `overrun` in the phrase list for the translation to be shortened. The takes are laid on the timeline, summed, brought to the integrated loudness of the original narration and mixed over the separated background into `dub_<lang>.wav`, which the page plays. Every take carries a version of its translation and slot: _Dub changes_ redoes only the phrases that moved or were retranslated (`scope` `changed`; `all` and `segment:<idx>` exist too). `POST /api/video/:game/:id/dub`, `GET /api/video-dub/:jobId`.
- **A dub the game plays.** The first packed intro was silent in the game: `loudnorm` hands its output on at 192 kHz, the mixer wrote that into the Bink file, and Bink stores the rate in 16 bits — 192 000 became 60 928 Hz. The speech bus goes back to 48 kHz 16-bit after loudnorm, the dub's version now includes the mix format (so an existing dub is remixed and repacked by _Dub changes_ without a new take), and the agent refuses a WAV the mixer would take but the game would not play. The phrase list plays each phrase's dub next to its take.
- **The agent does not dub its own dub.** With the videopack installed, the game's video file is our mix, and the next scan registered it as a new video — the fingerprint changed — forgetting the dub and uploading the mixed track as the narration. A video that Vortex's deployment manifest attributes to a `Transynth_<game>_<lang>_videopack_r<N>` mod is now read, scanned and mixed from `<file>.vortex_backup`, the game's own file Vortex keeps beside it. A dub the agent already wrote but the server no longer records as packed is reported again instead of mixed again.

- **Written back into the video, by the agent, with tools it fetches itself.** Bink 2 is written by nothing but RAD's own tools, so the agent downloads them from RAD's permanent link — a 7z (password `RAD`, as the download page says) holding an NSIS installer holding `radvideo64.exe` — and unpacks both layers in-process with 7-Zip compiled to WASM (`7z-wasm`), never running the installer; the one executable lands in `radVideoToolsPath` (default `%LOCALAPPDATA%\Transynth\vortex-agent\radtools`), on first need or with `--install-rad-tools`. The heartbeat now names the videos whose dub is not in their file yet; the agent downloads each dub, reads the video's track ids with `ffprobe`, runs `radvideo64.exe BinkMix … /TrackID<id> /SoundCompress4 /Overwrite /AutoClose` once per track (the picture is not re-encoded; the intro's two tracks take 4 s), reports `POST /api/video/:game/:id/packed`, and zips the finished videos into `Transynth_<game>_<lang>_videopack_r<N>.zip` in Vortex's downloads, a mod of its own next to the langpack. The mixer answers an error with a dialog, not an exit, so every pass runs under a timeout and counts only with exit 0 and an output file. `video_assets.packed_version`; `GameMediaAdapter.packDir`.

See [Dubbing the cutscenes](eng/18-video-dubbing.md).

## 0.10.0 — 2026-11-05

One registry for every service, and a controller that swaps them on one GPU:

- **Every external service in one registry.** The vLLM pool lived in a project setting; Fish Speech, audio-intel and bethesda-tools in three env variables with three clients and three notions of healthy. Each is now an endpoint of a kind — `llm`, `embed`, `tts`, `asr`, `separate`, `tools` — resolved from the project setting `services.endpoints` (**Settings → Services**, with a fresh health verdict and the pool load per kind; `GET /api/services` returns the same), then the older `llm.vllm_servers`, then the environment. Several rows of one kind form a pool of the shape the chat pool already had: each call goes to the least-loaded healthy host under that host's limit, a host that refuses connections leaves the pool until its probe passes, and a job that needs an unavailable kind waits instead of failing. With no rows every kind resolves exactly as before.
- **Jobs routed by the resource they consume.** `worker/src/core/jobKinds.ts` declares for every job kind its queue and the service kinds it needs. The `cpu` queue runs `JOB_CONCURRENCY` jobs at once; `llm`, `tts`, `asr` and `separate` are serial, one job each, so a service sees one job at a time while its pool parallelises inside the job. `WORKER_QUEUES=tts,asr` makes a worker serve only those queues, so a worker can sit next to the GPU that runs them. Queue names are unchanged; nothing migrates.
- **A fleet controller.** On a 32 GB card Gemma (29.4 GB), Fish Speech (25.5 GB) and audio-intel (7.7 GB resident, 12.1 GB peak) do not fit together, so an operator swapped them by hand before every batch. `npm run fleet` (compose profile `fleet`) reads `fleet.yml` — hosts with their GPUs and VRAM, services as compose projects with a declared VRAM, a priority and an idle limit — and every tick reads the queues, probes each service's `/health` and applies four rules: a wanted kind with no healthy provider gets its highest-priority service started if the VRAM fits; if not, residents that nobody wants, that carry no load and that idled past their own limit are stopped, lowest priority first; nothing else is stopped; operator overrides win. Compose runs on the host over ssh, because compose reads its files where it runs. Healthy services land in `services.endpoints` as `managed` rows next to whatever the kind already has, and web and worker re-read the setting every 30 s. `GET /api/fleet` and a Fleet panel on the Services tab show the GPUs, the services, the demand and the action log; `POST /api/fleet/services/<name>/start|stop` holds a service up or down for an hour.
- **Three things the first week in production taught.** A job that reaches a service its kind does not declare — a Disco import transcribing with audio-intel — writes `transynth:fleet:want:<kind>` while it waits, so the controller brings the service up anyway. Priority only orders who leaves first: an idle Gemma at priority 10 sat on the card for ever while a voice job waited for Fish Speech at 5. A service without a GPU (bethesda-tools) takes no VRAM, `keep: true` holds it up without demand, and several entries of one kind on several hosts are several instances the pool spreads calls over.
- **bethesda-tools needs nothing from Windows.** The image now carries xWMAEncode from the DirectX SDK next to FaceFXWrapper (Microsoft's download is gone; the Internet Archive's copy of the installer, checksummed), so `FonixData.cdf` is the one file left to supply: `npm run tools:install --game-dir …` copies it from the game or the Creation Kit. FaceFX and xWMA calls go through the `tools` pool like TTS calls and wait for a healthy instance inside a job. The native-Windows voice tool layer — the ffmpeg download, the local FaceFX and xWMA runs, the in-process Wine layer, the Steam library scan — is gone (+96 / −1207 lines).
- A client for audio-intel's separation lane (submit with `separate=true`, poll, download the tracks), the first consumer of its batch jobs; audio-intel calls wait for a healthy host the way TTS calls do.

See [Services and Queues](eng/14-configuration.md#services-and-queues).

Voice, from the first take to the pack:

- **Synthesis stops at the first take that passes.** The retry loop made the first take and then always `retries` more, whatever they scored — 366 requests for 46 lines at a gate of 0.4 and 8 retries. The budget is a ceiling now; the best take is still kept. The threshold and the budget are re-read from the settings before every line, so a change on the settings page applies to the running job.
- **A score for every take.** Takes made before the gateway could score (its image lacked the voiceprint model) and takes copied by reuse had no similarity, so the voice tab and the gate could not tell them from bad clones. `npm run voice:backfill-similarity` decodes each take, rebuilds its references the way live synthesis does and scores it through the gateway's new `/v1/similarity`: on Fallout4's pre-gate takes the mean is 0.31, against 0.38 for gated ones.
- **Re-synthesize what scored low.** A third item in the voice menu, _Low similarity…_, picks stamped takes below a threshold and runs them again with its own gate, target and retry budget; _Don't make it worse_ keeps the old take unless the new one scores higher. From Voice mode it runs for the selected character only. Every handled take carries the run's id, so a job resumed after a worker restart skips what it already did.
- **Reuse never copies an old translation.** The first pass of a voice job copies a donor take from another mod when speaker, source and translation match — and copied it together with its stamp even when the donor's translation had been reviewed after the take was made, so the audio said the old words. 811 such takes went into Fallout4. A donor whose stamp does not match its current text is skipped now, and a copy is stamped from the destination's own text.
- **A patch is dubbed against its masters' takes.** A Creation Engine voice line is keyed by the plugin that owns it, read off the FormID's master byte, instead of the lower six digits alone. A patch such as UFO4P that overrides a base-game or DLC line and changes its reviewed translation gets its own take with the master's take as the reference audio, under `Sound/Voice/<master>/…` in the patch's tree; the merged langpack orders the patch after its masters, and lines whose translation equals the master's are left to the master's pack. `voice_synthesis_state` and `voice_speaker_refs` gain `origin_plugin`, which joins the state's primary key; `db:init` rebuilds it (181,662 rows on the production base, seconds). The in-game check of a UFO4P pack is still to do.
- **The voice tab stays usable during a job.** A speakers request for Fallout4 took 74 s whenever a new take forced a catalog rebuild, because the rebuild rewrote `strings.voice_variant` for the whole mod and re-inserted every `voice_clips` row. The clip index is backfilled only for a mod that has none, and a build younger than 15 s is served even when takes moved on — the live stream patches the lines that changed. A patch job dubbing the player against ~13k base-game takes ran one auto-select scan per parallel line over the whole pool and could not be stopped; it is one resolution per speaker per job now, bounded to 240 takes, and Stop interrupts it.
- **The Fallout 4 voice pack reaches the archive.** Every FO4 langpack with voice failed since 0.6.0: the scratch folder holding `UASoundPack.esp` and its BA2 was removed before the entries were copied into the archive. The plugin writes into the staging tree itself now, and the 26 GB archive is built once. The BA2 is written through `fs.promises`, so the worker keeps its job lock and answers health probes while the 205k takes go through; before, the event loop blocked past the five-minute lock and the job was failed as stalled. Whether the game loads one uncompressed archive of that size is not verified yet.

See [Voice](uk/09-voice.md#запуск-синтезу). Run `npm run db:init` after pulling.

Two Ukrainian corpora read line by line, and what the reviews left in the repo:

- **Fallout 4 and Disco Elysium.** The base game and DLC (166,279 lines) with the reviewed mods (~40k lines) were proofread in scene context on 2026-10-21, and Disco Elysium's 90,802 rows on 2026-11-03: agents in batches, every fix validated and written with the old text as a guard, then unified corpus-wide. The reports, the decision logs, 285 glossary decisions and the ти/ви register table are in `doc/reviews/`; the Fallout 4 seed glossary (1,852 terms) is regenerated from the reviewed corpus.
- **The review pipeline, kept.** `npm run review:batches -- --mod <id>` cuts a mod into batches the way a reader needs them: quest conversations in phase order with speaker, addressee and gender on every line, a whole terminal or book, an item series by EDID stem, with the names each batch mentions and the QA hints of its lines. `npm run review:validate` checks an editor's fixes offline — stale text, changed tags or placeholders, slash gender forms, stray English, lost brackets — and `npm run translations:apply` writes the approved ones in one transaction, only where the stored text is still the old one, with a revision, a QA refresh, reference promotion and the stale RAG example dropped. Three skills in `.claude/skills/` (`corpus-review`, `fo4-uk-translate`, `translation-apply`) describe the process for the next game.
- **Names the translator can look up.** `src/games/creation-engine/data/names/fo4-uk.json` holds 3,870 names as the game displays them. Measured on the reviewed corpus, machine translation missed the canonical form of a name that is not a glossary term 42.4 % of the time, against 24.0 % for glossary names; so the names a source mentions (word boundary, at most 12 per request) are appended to the translate and verify prompts after the glossary terms, never embedded and never reaching QA. Putting them in the glossary was rejected: QA would flag 6,651 pairs on reviewed text (`Don` matches `Don't` 2,066 times). The live effect is still to measure.
- **Prompt and QA follow the canon the review settled.** Brotherhood proctors, knights and scribes on «ти», «ви» for Maxson and Kells only; the player speaks to Father on «ти»; `Sarcastic` on the dialogue wheel is `[Сарказм]`. A `tone_tag` QA warning flags a one-word wheel prompt translated without brackets — machine translation left 242 of 431 bare; the list is the prompts bracketed in at least 90 % of reviewed lines, not hand-picked.
- **Disco Elysium, from the review.** Translations never reached the pack: the exporter dropped the slashes from `.po` entry keys. Stars inside a word are censorship, not italics; `'ere`-style elisions are not title singles; four glossary pairs corrected; the translate and verify prompts carry the register pairs and the recurring machine errors the review found. A quote is cut out of the spoken text only when it holds at least two evidence words and none was heard: on the large-v3 transcripts of all 46,379 clips, wrong cuts went from 142 to 25, and the 168 lines whose spoken text changed are re-synthesized by the next voice job.
- **Long texts promote into the reference base.** Promoting a whole mod failed for every mod with a book or terminal entry — a 7,513-character source does not fit a btree row. The anchor key hashes the source text and the normalised-text lookup uses a hash index; Fallout4 promotes its 121,065 rows.

See [Fallout 4, 2026-10-21](reviews/fo4-uk-2026-10-21/README.md) and [Disco Elysium, 2026-11-03](reviews/disco-uk-2026-11-03/README.md).

Shipping faster:

- **A merge reaches the host in 3–6 minutes instead of 10–15.** A push to `main` whose tree is exactly the tree a green pull-request run already tested skips the checks and goes straight to the image; a diverged merge or a direct push runs them again. Format, lint and types, the unit tests, the SQL tests and the device tests run as four parallel jobs, and the deploy timer fires every minute.
- **The deploy stops the services before the schema step.** The schema file is one transaction over every table and deadlocked twice in a day against a running app session; a failed schema step starts the previous release again instead of leaving the host down.
- ffmpeg for the tests job comes from a pinned static build in the Actions cache instead of a 14-minute `apt-get`; the runtime image carries `openssh-client` for the fleet controller; `qa:refresh` and `rag:reindex` register the game plugins and no longer crash on `fo4`.

## 0.9.0 — 2026-10-10

The Witcher 3 (Remastered), text and voice:

- **A third game plugin.** `src/games/witcher3/` reads and writes the game's `.w3strings` tables (version 164, UTF-8; the key hash is over the lowercased key, which existing tools get wrong) and round-trips the shipped `en`, `pl`, `ru` and `ua` tables byte for byte. Remastered ships an official Ukrainian table, so importing the game brings 96,854 reviewed `uk` translations in with it, and the export reproduces that table entry for entry with the changed lines swapped in. Uploads take an archive; `npm run import:folder -- --game w3 --dir <install or mods folder>` reads an install or a mods folder in place, and is the generic folder import any plugin can offer.
- **Who says what.** Speakers come from the game's own scene files inside its `.bundle` archives: the voice tag of each line, who it is spoken to, and each tag's sex from `scene_voice_tags.csv`. Every one of the 64,718 voiced takes has a speaker (1,724 of them, all but 26 with a gender). Spoken lines are `W3D` records and reach the translator with the speaker's and the listener's gender; interface, books and journal are `W3S`. The dialogue view, the voice tab and the gender checks read the same data.
- **Voice without Wwise.** The game's takes are Wwise Opus inside a 4 GB `.w3speech` container, with a mouth animation per take in a bitwise-compressed buffer no public tool writes. Both are decoded and written here: the Opus packets are re-encoded with libopus in the layout the game expects (99.5% of re-encoded takes byte-identical), and the animation codec reproduces 64,708 of the game's 64,709 buffers exactly. `npm run w3:voice-pack` writes a `brpc.w3speech` for the Brazilian Portuguese slot, which the game has no Ukrainian one; `SpeechLanguage=BR` plays it.
- **A mouth model of our own.** Lip animation for a synthesized line is predicted from its audio by a small network trained on the animation CD PROJEKT RED made for the English takes (log-mel audio ±10 frames → 70 moving tracks of 148; held-out R² 0.54, jaw correlation 0.97). The trained weights ship with the plugin; `npm run w3:mimic-dataset` and `tools/witcher3-lipsync/train.py` retrain it from an install. Lip inference runs in worker threads that close after 5 s idle.
- **Cloning that knows the speaker.** Each line is cloned from its own take; a line too short to clone from alone adds its speaker's reference take or their longest other takes through the shared reference picker. Synthesis runs `voice.tts_max_parallel_fish_speech` lines at a time — for Disco Elysium too, which was sequential.
- **Prompts and glossary from the game's own Ukrainian.** The en→uk translate and verify prompts treat the scene genders as authoritative. The glossary was checked term by term against the official `ua` table and follows it where it departs from the book editions (Кер-Морен, Новіґрад, Скелліґе, Нільфґаард, Весемір, Реґіс, Дикий гін).
- Elder Speech in `{…}`, `<<Key>>` references and `$I$` tokens are masked out of translation like other markup. Voice routes accept the game's decimal line ids.

See [Voice](uk/09-voice.md#the-witcher-3-озвучення) and [Adding a game](uk/17-adding-a-game.md).

Two fixes from use:

- **Deleting a mod leaves a scanned plugin alone.** Delete removed every file the import job pointed at, and for a plugin registered in place by `scan:mods` that was the user's own `.esm` in the game folder. Only files inside mod storage or the Vortex upload area are removed now.
- **`npm test` runs in one recycled worker instead of one process.** Jest's ESM runtime keeps every finished suite's modules alive (about 13 MB a suite), so the 228 unit suites in one `--runInBand` process passed the default 4 GB heap and died with no suite reported. The suites still run one at a time, but `--workerIdleMemoryLimit` restarts the worker past 1.5 GB; the full run peaks at 1.75 GB whatever its size.
- **The app no longer freezes when Redis is down.** With the API up and Redis down, `/api/ai-jobs/active` never answered, the UI's 3-second poll piled requests behind it, and the browser's six connections per host filled up — every page looked dead. The route answers 503 within 3 s; the poll times out at 10 s and waits for one request to settle before sending the next.

Translations that outlive their mod:

- **A per-game reference base.** The translation memory was a query over other mods' rows, so deleting a mod forgot everything it had taught: strings, translations, RAG examples and synthesized voice went together. `reference_translations` holds reviewed and human translations with their TM anchors and no foreign key to any mod. TM auto-apply reads it ahead of live mods on the same anchor; an identical live source text still wins over a normalized-text reference match.
- **Three ways in, one way to protect.** Right-click → _Mark as reference_ in the editor; a _Keep reviewed translations in the reference base_ checkbox in every mod delete dialog, on by default, that snapshots before the purge; and a Workflow setting that promotes a translation the moment it becomes reviewed or human. A row edited by hand on the Reference page is never overwritten by a promotion.
- **An editable Reference page per game.** Game hub → _Reference base_: filter by language pair, search source, translation or EDID, add a pair by hand, edit or delete rows, and promote one mod or the whole game. Editions that share a glossary (Skyrim LE and SE) share a reference base.
- **A reference hit is approved on the spot.** TM auto-apply writes an exact match from the reference base as `reviewed`, not `tm`: the row was reviewed once already. A number transplant is new text and stays `tm`. Such rows carry `tm_reference_<method>` provenance, and the editor's TM toast counts them.
- Not yet: RAG examples and synthesized voice are still mod-bound. A reference row feeds TM matching only.

See [Translation memory](uk/05-translation-memory.md#еталонна-база). Run `npm run db:init` after pulling.

Usable from a phone or a tablet:

- **Device tests.** `npm --prefix web-ui run test:devices` opens every page on a desktop, a laptop, an iPad both ways round and three phones down to 320px, in Chromium and WebKit, against a fake API. It fails when a page grows wider than the screen, a top-bar control falls off it or is under 24px to tap, or an editor line cannot be opened by a finger. CI runs it on every pull request.
- **What they found, fixed.** On a phone the top bar pushed every page sideways, the Settings sidebar and label column left no room for the fields, wide tables widened the page, and mod rows crushed their names to nothing. The top bar now wraps to two rows and scrolls away, settings stack into one column, tables scroll inside their own box, and mod rows put progress and actions under the name.
- **The editor works by touch.** A tap opens a line (a mouse still selects on click and opens on double-click), the record-type list becomes a strip above the grid, original and translation stack, and the divider between grid and detail panel drags with a finger.
- **The editor fits a narrower window, not only a phone.** The grid's fixed columns needed about 1000px and could not scroll, so on a tablet or a small laptop source and translation sat past the edge; as the grid narrows it now drops Field, EDID, then FormID and the action buttons. The toolbar used to clip from the left on anything under ~1100px, hiding the mod name and the AI buttons; it now wraps.
- **A phone shows one thing at a time.** Opening a line in the editor used to split a 568px screen three ways, each part scrolling on its own; now the line opens as a full-screen sheet with a _Back to list_ button. The dialogue and voice screens put their navigator above the content instead of beside it, and the toolbar drops the language pickers and the shortcut help there. A _Row actions_ button in the detail panel opens the same menu as a right-click on the grid, so a finger (and anyone who never right-clicks) can reach it; the menu itself no longer runs past the bottom of a short screen.
- **Tables read as cards on a phone.** The glossary, the reference base and the QA rules stack each row's cells into a card instead of scrolling a five-column table sideways, so the edit and delete buttons are always in reach; on a tablet those buttons stay pinned to the right edge while the rest scrolls. The Settings tab strip scrolls the chosen tab into view and fades at the edge to show there is more.
- **Smaller fixes from looking at every page on every device.** Buttons and selects use the page font (WebKit drew some in a serif), dense tables keep a minimum width and scroll instead of breaking words letter by letter, long archive names no longer run over the import progress, and mod rows stack on tablets as well as phones.

Tests that run the SQL:

- **A database suite.** Until now no test ran a query against Postgres — the few query tests passed a fake `query` and checked the call. `npm run test:db` runs `*.db.test.ts` against a real one, the same pgvector image production uses; `npm run test:db:up` starts a throwaway server with its data in RAM, and CI runs the suite on every pull request. The suite refuses any database whose name does not end in `_test`, because it drops and recreates it.
- **What it covers first.** `db:init` re-applied over live data; TM auto-apply with the reference base (reference beats a live mod on the same anchor and is approved at once, an identical live source beats a normalised reference match, a number transplant stays `tm`, Skyrim LE and SE share one base); deleting a mod, with and without the reference snapshot, and the next version of the mod picking up what the deleted one taught; saving a translation, changing statuses, and the auto-promote setting. Each rule was checked by breaking it on purpose and watching a test fail.
- **The API that writes data, tested over HTTP.** Strings (save, clear, ignore, statuses, skip, TM apply), mods (delete, batch delete, empty, clear copies of the source), the reference base, project settings, the glossary, QA rules and deleting an import job go through the real routes with `app.inject`, against the same database.
- **What those tests caught.** Saving a line with a status the editor does not know stored it, and the line then matched no filter in any view; it is now refused. A blank glossary term was stored as an empty term. A `max_length` QA rule accepted `32px` (stored as 32px, read as 32), and an edit that changed only the value skipped the check entirely. A non-numeric import-job id in the URL reached SQL and came back as a server error instead of a 400.
- **The worker's decisions, without a model.** The chat call is replaced and nothing else: the real request is built and the real response parser throws the real errors. Translate keeps every validated row of a batch, restores placeholders, refuses a plain-text answer that lost one, retries a missing row on its own and a timed-out batch in halves; skip-detect asks the model only about what the heuristics left and marks nothing when the model fails; verify writes a fix for a proven defect only when its detector stops objecting, writes advice only when it beats the current wording, records the model's unaided objections on the row, approves what passed, never a rejected line, and writes nothing on a dry run.
- **Imports, tested on real files.** Plugins built byte by byte, real zip archives unpacked by 7-Zip, and synthetic ESP-ESM Translator files: registering an upload (sized by its strings, localized flag, the same file uploaded again under another name, Nexus details filled in but never overwritten), PEX script literals, MCM keys, and CSV and EET registration.
- **Import bugs those tests caught.** A CSV whose quoted field spans lines — book pages, long dialogue — was split on line breaks: the translation was lost and pieces of the text became FormIDs of phantom records. The parser now splits records the way RFC 4180 says, and the line-at-a-time parser it replaces is gone. Script text shown only through `Debug.MessageBox` was dropped from import when the script could not be decompiled, because the debug-call pattern read MessageBox as `Debug.Message`. The EET reader tests needed sample files that are not in the repository and so passed without checking anything; they now show as skipped, and synthetic EET files test the reader everywhere.
- **The web UI’s own logic, unit-tested.** Editor autosave, the editor’s filters and their place in the address, row selection (including “select all matching” with exceptions), the AI job poll and the translate runner, and the API client’s error handling.
- **Web UI bugs those tests caught.** Text typed in the editor and left within the 800 ms autosave window — a nav link, the back button — was thrown away; it is now saved on the way out. When a finished AI job’s “completed” badge was still showing, a new run of the same kind on the same mod stayed hidden, and the old badge never went away, so the new run’s end never showed either, until a reload.

EET and CSV uploads land under the right game:

- **Filed under the page they were uploaded on.** An EET or CSV upload sent no game, so every one became a Fallout 4 mod whatever page it came from, and nothing in the UI could change that afterwards. Both now carry the page's game and your source and target languages, as a mod upload does; a mod upload now sends the languages too. Uploading the same file from another game's page moves its mod there.
- **An EET file for another game is refused.** The EET header names its game. When that name clearly means a different game from the page — a `Skyrim` file on the Fallout 4 page — the upload is refused with a message saying which game the file is for, and nothing is written; an earlier upload of the same name is left intact. Editions that share their text count as one game, and a name no game claims is not checked. Refusing beats both alternatives: filing it under the page game imports Skyrim text into Fallout 4 before anyone reads a warning (the import starts on upload), and filing it under the header's game puts it on a page the user is not looking at.
- **A failed upload says so.** An error from any upload in the picker used to vanish and stop the rest of the selection; it now shows as a toast and the other files go on.

## 0.8.0 — 2026-09-25

Verify settles a line in one run, and the LLM pipeline stops working against itself under load:

- **A proven gender leak is repaired before the audit, not after it.** The leaking rows of a batch go to the gender pass first, the repaired wording is written, and the model then judges the text that will actually be approved. One verify run takes a line from leaking to `reviewed`; it used to take two, with an audit call spent on text the detector already knew was wrong. A line the pass cannot fix still blocks, and is not sent to the same pass again in the same run.
- **The gender pass offers three rewordings and the detector picks the first clean one.** Asking for one wording left one line in six unrepaired — the model's first attempt patched the verb or left a marker elsewhere. Measured on 60 real leaking Fallout 4 lines with the same detector on both sides: 55 clean before, 59 after. The detector also reads «відволікся» and «ти що, здурів?».
- **A fix for a proven defect answers to its detector; advice answers to the comparison.** A defect the system proved no longer goes through the model's "which is better" call — it is accepted when the detector stops objecting. The comparison stays for advice, and when it fails nothing is written: it used to keep every candidate, opening the gate exactly when the server was saturated (403 times in three days of production logs).
- **Glossary embeddings work for the first time.** The glossary's two thousand terms were sent to the embedding server as one request, refused with HTTP 413, and asked again on every batch — 54,558 refusals in three days, a wasted round trip per LLM call, and the semantic fill never ran. Terms are now embedded in batches, once per process; a failed build is remembered for ten minutes.
- **A timed-out batch retries in halves, not as one request per row.** Twenty-five solo requests each carrying the same ten-thousand-token system prompt were the worst reply to a saturated server; the logs show 204 batch timeouts turning into thousands of solo calls that timed out in their turn. Translate, verify and skip-detect now bisect.
- **A source rewrite keeps the rows the model did translate.** One row returned blank used to fail the whole batch, and the same few long sources sank their neighbours on every run.

## 0.6.0 — 2026-09-15

A game is a plugin, and Ukrainian that reads like Ukrainian:

- **Adding a game means writing a plugin, not editing the whole codebase.** Everything a game decides — which records hold text, how its markup is protected, its prompts and glossary, its import, export, voice and deployment — lives in one folder under `src/games/` behind a single contract. Shared code no longer names a game or an engine: `GRUP`, `.esp` and Bethesda's record signatures stay inside the Creation Engine plugin, and a test fails the build when a new reference leaks out of one. See [Adding a game](uk/17-adding-a-game.md).
- **Disco Elysium dialogue has speakers.** The grid, the scene window and the prompts were resolving nobody for any of its 90,802 lines; the game now answers who speaks and who is spoken to, and 41,431 lines carry a resolved participant. Harry is named as the addressee, and a speaker's gender is read out of the surrounding text when the data does not state it.
- **Fewer gender and calque errors.** Speaker gender is no longer decided by a three-pronoun window, and internal voices, the player character and unnamed NPCs are handled explicitly instead of falling through to male. Eleven Russian-calque patterns are checked after the model answers; the four worth their tokens are also in the prompt.
- **Verify holds a line only on a proven defect.** A broken token, broken markup, a gender leak or a corrupted translation — things the system can check itself. A bare `suspicious` (calque, tone, register) is written to `qa_issues` as `llm_review` and shown in the editor, and the row goes to review instead of circling through a dozen rewrites. On base Fallout 4 that took the pool from 998 to 98; 771 of 869 rows approved, 721 carrying their critique. A rewrite that repeats a wording the row already had is refused, advice stops after five attempts, and a new wording has to beat the incumbent. A proven defect is never capped.
- **Gender repair is three prompts, not one.** A participant whose gender is known just needs the ending changed; a line the player says about themselves, or an NPC says to the player, needs a construction rewrite. One prompt covering all three contradicted itself and rewrote Curie's log from a correct feminine into a wrong impersonal. The branches run one after another. The detector now reads subjectless clauses and predicative adjectives — Ukrainian drops subjects constantly — and an inferred narrator gender is no longer evidence: only a person's own decision gates a narration row.
- **QA is visible while translating.** A dialogue row shows what QA found on it and whether the translation came from memory or the model, so a gender fix is findable instead of buried in another tab. Speaker colours now meet WCAG AA in both themes.
- **One `voice_clips` table for every game** instead of one per engine, with columns named for what they hold (`line_key`, not `formid_lower6`).
- **Documentation checked against the code.** Broken links, renamed scripts and undocumented features are fixed, dead CLI pages and one-off dev scripts are gone, and the Vortex sync page now says outright that the feature is experimental and at a very early stage.
