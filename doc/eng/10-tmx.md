## What is TMX?

**TMX 1.4b** is an open XML standard for exchanging Translation Memory data
between different translation tools.
Virtually every professional CAT tool supports TMX import and export.

A TMX file contains translation unit pairs:

```xml
<tu>
  <tuv xml:lang="en"><seg>Take care, wanderer.</seg></tuv>
  <tuv xml:lang="uk"><seg>Бережись, мандрівнику.</seg></tuv>
</tu>
```

---

## TMX vs Release Workflow

TMX is a **translation-memory maintenance surface**, not the final release surface for an updated mod.

Use **TMX** when you need to:

- share translation memory with another CAT tool or teammate;
- back up the current translation memory;
- seed a new project with previously translated material.

Use **Diff + Mod Editor export** when you need to:

- compare an updated mod version with the previous version;
- carry over old translations into the new version;
- review drafts and resolve QA blockers;
- export STRINGS, BA2, or ZIP for the actual release package.

## Exporting TMX

Navigate to **TMX** in the top navigation bar (route: `/tmx`), then use
the **Export** section.

The export section has two controls:

- **Mod (optional)** — a dropdown listing all imported mods. Leave it
  set to "All mods" to export the complete TM. Select a specific mod to
  export only the translations for that project.
- **Target language** — the language of the translations to export.
  Available options: Ukrainian, Russian, German, French, Spanish.

Click **Export TMX** to download the file. The file is generated on the
server and downloaded immediately with a name that reflects the scope:

- `tm_all_{srcLang}_{tgtLang}.tmx` (global export, e.g. `tm_all_en_uk.tmx`)
- `tm_mod{id}_{srcLang}_{tgtLang}.tmx` (single-mod export, e.g. `tm_mod42_en_uk.tmx`)

Export scope:

- **All mods** — exports every saved translation in the database.
- **Single mod** — exports only translations for that mod.
  Useful for sharing work on a specific project.

The downloaded file is named:

- `tm_all_en_uk.tmx` (global export)
- `tm_mod42_en_uk.tmx` (per-mod export)

## Importing TMX

Use the **Import** section on the TMX page to load a TMX file from another tool.

The import section has two controls:

- **Match against** — a dropdown. Leave set to "All mods (global)" to
  match imported units against every string in the database, or pick a
  specific mod to restrict matching to that mod's strings.
- **TMX file** — a file picker that accepts `.tmx` and `.xml` files.

Click **Import TMX** to upload and process the file.
The button label changes to "Importing…" while the request is in flight.

After the import completes, a summary is displayed below the form:

```
Parsed: 1 240 · Imported: 820 · Skipped: 420
```

- **Parsed** — total translation units read from the TMX file.
- **Imported** — units that matched a source string and created a new
  translation in the database.
- **Skipped** — units that had no matching source string, or matched a
  string that already has a translation in the database.

**Conflict policy:** If a matching source string already has a `reviewed`
or `human` translation in the database, the imported entry is skipped —
existing high-quality translations are never overwritten. If the string
has a lower-quality translation (`draft`, `tm`, `fuzzy`, `auto`,
`rejected`), it is also skipped — the existing entry is kept regardless
of its quality.

Imported translations receive `status = 'tm'` with
`provenance = 'tmx_import'`.

## Compatibility

TMX 1.4b files generated by this tool are compatible with:

| Tool              | Notes                                            |
| ----------------- | ------------------------------------------------ |
| SDL Trados Studio | Import/export TMX via Translation Memories panel |
| memoQ             | Import via Translation Memories → Import         |
| OmegaT            | Place `.tmx` in project's `tm/` folder           |
| Wordfast          | Import via TM Manager                            |

The exported TMX uses standard UTF-8 encoding, `xml:lang` attributes on
`<tuv>` elements, and no vendor-specific extensions — it is plain
TMX 1.4b and should import cleanly into all listed tools without any
mapping or namespace adjustments.

## Use Cases

- **Team collaboration** — a translator working in OmegaT can import your TMX
  as a reference, or export their TMX for you to merge back.
- **Backup and migration** — export the full TM before moving to a new machine.
- **Seeding from existing translations** — if you have a translation file from
  another project, convert it to TMX and import it to jump-start your TM.
