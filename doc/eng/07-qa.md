## Overview

Before exporting your translation, the QA engine scans every translated string
and flags potential problems.

QA is not blocking — you can export even if issues exist — but reviewing
QA flags ensures a polished, professional localisation.

---

## Running a QA Check

QA runs automatically — there is no separate "run QA" button.

**Automatic on save:** Every time you save a translation (via Ctrl+S, Ctrl+Enter,
or any status change), `refreshQAIssues` runs immediately for that string.
Issues appear in the **QA** tab of the Detail Panel the next time you open it.

**QA count badge in the grid:** If a string has active QA issues, a small
badge `N QA` is shown in the translation column next to the translated text.
This makes it easy to spot strings with problems while scrolling.

**QA tab in the Detail Panel:** Select any string and open the **QA** tab
to see all issues for that string. Each issue shows severity (ERROR or WARNING)
and a descriptive message explaining what is wrong.

## QA Issue Types

| Issue Type                       | Internal Key              | Severity      | Description                                                                                                                                                                                                                                                                                                                         |
| -------------------------------- | ------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Empty translation**            | `empty_translation`       | Error         | The string has a source text but the translation is empty or whitespace only.                                                                                                                                                                                                                                                       |
| **Placeholder mismatch**         | `placeholder_mismatch`    | Error         | Placeholders in the translation don't match the source. A token is missing, added, or different.                                                                                                                                                                                                                                    |
| **Same as source**               | `same_as_source`          | Warning       | The translation text is byte-for-byte identical to the source text. Usually indicates an untranslated string.                                                                                                                                                                                                                       |
| **Length delta**                 | `length_delta`            | Warning       | The translation is more than 1.6× longer or less than 0.5× as long as the source (minimum 20-char source). Unusually short or long translations often indicate a problem.                                                                                                                                                           |
| **Forbidden control characters** | `forbidden_chars`         | Error         | The translation contains invisible control characters (C0/C1 Unicode range, null bytes) that cannot render in-game.                                                                                                                                                                                                                 |
| **Glossary violation**           | `glossary_violation`      | Warning       | The source text contains a glossary term (matched with word boundaries — e.g. "iron" won't match inside "environment") but the translation does not contain the expected target-language equivalent.                                                                                                                                |
| **Gender mismatch**              | `gender_mismatch`         | Error/Warning | Ukrainian only. A gendered past-tense verb or predicative adjective next to «я» or «ти» disagrees with the speaker or addressee resolved from the dialog graph. Error when the participant has a known gender, warning when the participant is the player character (whose gender is chosen in game, so no committed form is safe). |
| **Duplicate inconsistency**      | `duplicate_inconsistency` | Warning       | The same exact source `text_raw` within the same record `signature` is translated differently elsewhere (up to 5 alternatives shown).                                                                                                                                                                                               |
| **Custom forbidden chars**       | `forbidden_chars`         | Configurable  | A configurable rule explicitly lists characters that must not appear (e.g. characters outside the game font table).                                                                                                                                                                                                                 |
| **Max length exceeded**          | `max_length`              | Configurable  | A configurable rule defines the maximum character count for a specific GRUP or field.                                                                                                                                                                                                                                               |

Properly extracted placeholders include: `%s`, `%d`, `{0}`, `{item}`,
`<Alias=Player>`, `<b>`, `$PlayerName`, `[DIAL:001234AB]`.

**Examples:**

```
[placeholder_mismatch]
Source: "Hello, <Alias=Player>! You have {0} caps."
Translation: "Привіт! У вас є {0} кришок." ← <Alias=Player> is missing
Issue: Placeholder mismatch: source=[<Alias=Player>, {0}] target=[{0}]

[same_as_source]
Source: "Pip-Boy"
Translation: "Pip-Boy" ← unchanged
Issue: Translation is identical to source text.

[glossary_violation]
Glossary: synth → синт
Source: "Kill the synth."
Translation: "Убий синтетика." ← doesn't contain "синт"
Issue: Glossary: "synth" should be translated as "синт".
```

## Severity Levels

There are two severity levels — no `Info` level exists in the current implementation.

| Severity    | Meaning                                                                                                                 | Recommended Action |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------ |
| **Error**   | Will certainly cause problems in-game (broken placeholder, empty translation, control characters)                       | Fix before export  |
| **Warning** | Likely to cause issues or look unprofessional (same as source, length anomaly, glossary miss, inconsistent translation) | Fix if possible    |

## Configurable QA Rules

Some QA checks are configurable per-game and per-record type.
Manage rules in **Settings → QA Rules**.

### Forbidden Characters

A `forbidden_chars` rule defines a set of characters that must not appear in
any translation matching the rule's scope.

The **Value** field contains the literal forbidden characters as a string —
each character in the string is checked individually. For example, entering
`©®™` forbids those three characters. Non-printable characters should be
copied directly into the field or entered as their literal code point.

**When to use:** The Fallout 4 engine uses a fixed font atlas; characters
outside that atlas render as boxes or are silently dropped. Add a
`forbidden_chars` rule for any character set that your specific target
language font does not support.

**Scope:** Optionally restrict the rule to a specific record type (GRUP
signature, e.g. `DIAL`) and/or field path (e.g. `FULL`). Leave blank to
apply the rule to all strings in the game.

### Max Length

A `max_length` rule defines the maximum number of **characters** allowed in a
translation for a specific scope.

The **Value** field must be an integer string (e.g. `128`).

**When to use:** Bethesda's UI elements have fixed display areas. Long
translations in `FULL` (item names, NPC names) can overflow or be truncated
in quest logs and HUD elements. Short descriptors like `SHRT` (short names)
have tighter limits than full descriptions (`DESC`).

**Scope:** Restrict the rule to a specific signature and/or path. Examples:

| Signature | Path   | Max   | Use case             |
| --------- | ------ | ----- | -------------------- |
| `WEAP`    | `FULL` | `50`  | Weapon display names |
| `NPC_`    | `FULL` | `40`  | NPC names            |
| _(any)_   | `DESC` | `512` | Description fields   |

Leave signature/path blank to apply globally across all strings.

Max length rules count characters, not bytes. For cyrillic text each character
is one regardless of UTF-8 encoding.

## Filtering by QA Status in the Editor

There is no dedicated "QA status" filter in the status dropdown. Instead,
QA issues surface in two ways:

1. **Badge in the grid:** Any row with active QA issues shows a small `N QA`
   badge next to the translation text. Scan visually while reviewing.

2. **QA tab in the Detail Panel:** Select a string with a badge and click
   the **QA** tab to see the full list of issues with severity and message.

**Efficient review workflow:**

1. Filter by the status you want to review (e.g. `auto` or `tm`).
2. Scan the translation column for `N QA` badges.
3. Click any flagged row to open the Detail Panel → QA tab.
4. Fix the issue in the translation textarea.
5. Save with **Ctrl+S** — QA re-runs automatically and the badge disappears
   if all issues are resolved.
6. Press **N** or **↓** to move to the next row.

## QA Rules Page

The QA Rules tab in Settings lists all configured rules and lets you:

- **View** existing rules in a table (type, signature, path, value, severity,
  description, active toggle).
- **Create** new rules using the add form at the top of the page.
- **Inline-edit** any rule row — click the **Edit** button on a row to switch
  it into edit mode; click **Save** to commit or Cancel to discard.
- **Toggle active/inactive** — inactive rules are stored but do not run.
- **Delete** a rule permanently with the Delete button.

**Add/Edit form fields:**

| Field       | Required | Description                                                                            |
| ----------- | -------- | -------------------------------------------------------------------------------------- |
| Rule type   | Yes      | `Forbidden chars` or `Max length`                                                      |
| Signature   | No       | Restrict to a GRUP (e.g. `DIAL`, `NPC_`); leave blank for all                          |
| Path        | No       | Restrict to a field (e.g. `FULL`, `DESC`); leave blank for all                         |
| Value       | Yes      | For `forbidden_chars`: the literal forbidden characters. For `max_length`: an integer. |
| Severity    | Yes      | `error` or `warning`                                                                   |
| Description | No       | Human-readable label shown in QA issue messages                                        |

All rules are scoped to game `fo4` in the current build.
